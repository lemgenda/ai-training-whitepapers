1. Abstract

The LemGendary AI Ecosystem is an end-to-end, hardware-aware deep learning platform for vision restoration, perceptual quality assessment, object detection, a causal LLM assistant and multi-timeframe quantitative finance. This manifest records the operational state verified on 2026-11-03 against the code and the README changelogs of the five project repositories.

Current capabilities:

  • Tripartite Services: Three decoupled FastAPI sidecars with HTTP REST and live WebSocket channels (ports 8000, 8100, 8200), each bound to 127.0.0.1 and described by its own OpenAPI 3.1.0 openapi.json (32, 38 and 40 operations).
  • Shared Security Contract: Every sidecar runs the same Origin Guard. Browser requests from origins other than the LemGendary AI Studio GUI (tauri://localhost, http://tauri.localhost, https://tauri.localhost, http://localhost:1420, http://127.0.0.1:1420) get HTTP 403, and state-changing browser requests must send the Client Header X-LemGendary-Client: ai-studio-gui. GET /api/secrets returns only whether each secret is set and its last 4 characters.
  • Presentation Layer: The LemGendary AI Studio GUI (v2.10.19), a cross-platform desktop cockpit built with Tauri v2, React 18 and Vite, with a real Content Security Policy and one shared fetch wrapper for all sidecar calls.
  • Bug Report Tool: The header button "Report Issue" opens a form (email, module, description of at least 50 characters, up to 5 annotated screenshots, optional Telemetry CSV). POST /api/bug-report on the LemGendary Environment Manager saves a Bug Report Archive (ZIP) in the workspace and opens the user's own mail client; no SMTP password ships with the application. Screen recording is planned (deferred by the owner).
  • Monotonic Ratchet (pair rule): Resolution never decreases, and the data fraction never decreases within one resolution step; it may reset when the resolution steps up. A backward step raises RatchetViolation.
  • Bounded Epoch Budget: Training stops on convergence (4-pillar completion), on the governor's early stop or when the configured budget is spent; extensions are opt-in and capped.
  • Pareto Model Soup: lemtrain soup and POST /api/models/{model_key}/soup blend vault checkpoints. Stochastic Weight Averaging (SWA) is not implemented.
  • Publication-Grade FID: FID uses the 2048-dimensional Inception pooling layer in micro-chunks of at most two samples. Historical FID values of codeformer, ffanet_indoor, mprnet_deraining and mirnet_lowlight are FID unverified (rewritten by a removed tool) until the checkpoints are re-evaluated.
  • Non-Destructive Pipelines: The Run Pipeline action is non-destructive by default; a clean run needs an explicit option and a confirmation dialog.
  • Zero-Hang Pipeline Lifecycle: GUI pipeline completion recovers from all terminal statuses (success, warning, error). A 1,500 ms reconciliation poll against /api/pipeline/status and an isLatestCompleted guard in PipelineStepCards.tsx keep step cards from staying in RUNNING.
  • OpenCV Variant Equivalence: health_checker.py treats the four OpenCV distributions (opencv-python, opencv-contrib-python and their -headless counterparts) as mutually satisfying.
  • Toolchain Modernization: mosaicml-streaming is removed; Lightning AI LitData and WebDataset are the canonical streaming primitives. Ruff (>=0.9.0) replaces Pylint and astroid.
  • Physical MDS Transcoding: 110.9 GB of legacy .mds.zstd shards were transcoded to WebDataset .data archives: LemGendizedClassificationMaster (68.7 GB, 789 shards; 693,040 train + 94,965 val samples) and LemGendizedMultitaskRestorationPro (42.2 GB, 54 shards; 232,464 train + 31,742 val samples).
  • cu126 PyTorch Stack: torch 2.14.1+cu126, torchvision 0.29.1+cu126, torchaudio 2.11.0+cu126, transformers 5.20.1, sympy 1.14.0 and numpy 2.1.3 in lemgendary-training-suite and lemgendary-datasets. select_cuda_torch_index() in system_probe.py picks the newest supported index (cu126, cu121, cu118) from the driver version.

6. Manifold Ingestion & Container Modernization

  • Storage Location: LemGendary Compiled Manifolds Repo (LemGendaryDatasets/, suffix-free directory topology).
  • Container Formats: WebDataset (.data/.tar), Lightning AI LitData (.bin), Apache Parquet (.parquet), Directory (.webp). The registry canonical formats are webdataset for vision models, parquet for forex_predictor and directory for yolov8n.
    • Deprecated: MosaicML MDS (.mds). All legacy .mds.zstd shards were transcoded to WebDataset .data archives. The .data extension is canonical across the ecosystem, bypassing Kaggle backend archive-sniffing heuristics that would otherwise expand multi-gigabyte containers into loose files.
  • Transcoding Standard: In-flight 12-thread WebP zero-intermediate compression:
    • Input/Degraded: WebP Lossy ($q=92$).
    • Ground Truth Target: WebP High-Fidelity ($q=95$).
    • Alpha / Segmentation Masks: WebP Lossless.

7. Cloud Training & Remote Synchronization Pipeline

  • Kaggle Pipelines (kaggle_training/): 23 standalone notebooks consuming attached input datasets directly from /kaggle/input/ with zero redundant cloud downloads.
  • Google Colab Pipelines (colab_training/): 23 automated training pipelines synchronized idempotently to Google Drive via push_to_drive.py.
  • Kaggle Models Hub 4-Variation Publishing (lemtrain sync push):
    • Publishes 4 strictly isolated variations per model: pytorch/default (checkpoints and metrics), pytorch/fp32 (native .pt), onnx/fp16 (half-precision graph) and onnx/fp32 (full-precision graph with .data sidecar).
    • Metadata comes from LemGendaryModels/<key>/model_metadata.yaml and is synchronized to the Kaggle REST API with resolved owner credentials.
    • Full fleet synchronization (lemtrain sync push --all) sequences all 23 registered models with per-model progress telemetry routed to the Local Telemetry tab; Kaggle job events go to the Remote Cloud telemetry tab.
  • Bidirectional Metadata Sync:
    • push_kaggle_dataset_metadata verifies that the remote repository exists via ensure_kaggle_dataset_exists.
    • If a target dataset slug does not exist on Kaggle, the synchronizer creates a minimal public placeholder dataset containing README.md first, which prevents 403 Forbidden errors during metadata updates.
    • PowerShell (lemgendary_datasets_hub.ps1 options 3 and A) and the LemGendary AI Studio GUI (CompilerPanel.tsx "Update Metadata Only" tab) update metadata without re-uploading multi-gigabyte data archives.

8. Hardware Sentinels & Physical Execution Constraints

  • GTX 1650 (4GB VRAM) Edge Baseline: Sub-nuclear 4GB lockdown enforces Serial-Only Mode upon memory saturation, eliminating Windows System RAM pagefile thrashing (empirically measured $12.5\times$ batch retrieval acceleration from 3.43s down to 0.27s per batch when memory-mapped sequence manifolds on Windows enforce num_workers=0).
  • CUDA 12.6 Verified (cu126): NVIDIA GeForce GTX 1650 (Turing, sm_75, Driver 610.74) verified with torch 2.14.1+cu126. Hardware gates confirmed: FP32 matmul, FP16 autocast, Conv2D forward/backward, torch.compile eager fallback, ONNX Dynamo export (max diff 1.78e-07), Transformers 5.20.1 BERT/GPT2 CUDA inference and Torchvision CUDA NMS. BF16 is unsupported on Turing as expected and is not selected.
  • Continuous Memory Formula: Dynamic batch calculation scales continuously with available VRAM:
$$B_{\text{safe}} = \left\lfloor \frac{\text{VRAM}_{\text{total}} \cdot \text{safety} - \text{static\_overhead}}{\text{mem\_per\_sample}(\text{resolution})} \right\rfloor$$
  • Sawtooth VRAM Governor: Halves batch sizes when memory pressure exceeds 90% and scales up when headroom exceeds 40%.
  • Sub-Second Minibatch Cancellation: Evaluates non-blocking cancellation listeners at batch boundaries, terminating execution within one batch cycle upon operator abort signals. Stop Training in the GUI shows an error when the cancel request fails.

9. Zero-Suppression Policy Compliance

The codebase follows the zero-suppression rules of ROBOTS.md across all languages:

  • Python: no # type: ignore, # noqa or # pylint: disable directives and no programmatic warnings.filterwarnings suppressions.
  • TypeScript & JavaScript: no @ts-ignore, @ts-expect-error or /* eslint-disable */ directives and no configuration diagnostic suppressions (warnOnUnsupportedTypeScriptVersion: false is banned).
  • Markdown: no inline markdownlint-disable directives in the documents synchronized during the 2026-11 remediation.
  • Zero Silent Crashes: Bare except: pass and empty catch {} blocks are forbidden. All errors must be explicitly typed, logged or surfaced to operators.
  • Root-Cause Resolution: Warnings, type checks and dependency vulnerabilities are resolved through static type annotations, Pydantic schema validation, safe package upgrades and defensive programming.

10. Background Process Lifecycle Governance & Zombie Elimination

The ecosystem enforces deterministic process lifecycle management to prevent orphaned child processes and CPU/VRAM resource leaks:

  • Recursive Process Tree Elimination: Sidecar shutdown (service_manager.stop_service) and job cancellation (jobs.py) execute recursive tree termination (taskkill /F /T /PID on Windows, recursive signal propagation on POSIX), terminating both parent orchestrators and all spawned worker subprocesses.
  • Guaranteed Cleanup Handlers: atexit child process sentinels prevent detached PyTorch training loops, Uvicorn workers or compilation scripts from persisting after cancellation or abnormal exit.
  • Telemetry & Unzip Progress Synchronization: Kaggle dataset decompression streaming (kaggle_importer.py) and multi-stream telemetry tracking (TelemetryProgressTracker.tsx) keep operator progress bars in line with the physical disk and training state.
