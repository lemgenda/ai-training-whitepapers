1. Executive Overview

The LemGendary Ecosystem comprises seven specialized repositories orchestrated under a unified architectural contract. All command-line operations are standardized, deterministic, and free of external visual noise or emojis. The single authoritative command-line tool for ecosystem health, virtual environment lifecycles, and verification is lem-env, located in lemgendary-env-manager.

Every toolchain command adheres strictly to semantic exit codes, making them directly suited for automated continuous integration, local terminal workflows, and cross-project orchestration.

2. Environment Manager CLI (lem-env)

lem-env is packaged as a standard Python console application using Typer and Rich. It provides the central management interface for inspecting hardware capabilities, provisioning isolated virtual environments, upgrading packages in dependency order, and enforcing strict linting and compilation gates across all seven workspaces.

2.1 Global Options & Invocation

# General invocation syntax
lem-env [COMMAND] [OPTIONS]

# Help and discovery
lem-env --help
  • --help: Type: Flag; Description: Display comprehensive command usage, available subcommands, and flags

2.2 Hardware Probing (probe)

The probe command discovers system hardware, compute accelerators, operating system architecture, MetaTrader 5 availability, and checks for software update releases against upstream registries.

lem-env probe

Key features:

  • Detects GPU acceleration backends including NVIDIA CUDA, AMD ROCm, Windows DirectML, and CPU fallback.
  • Detects MetaTrader 5 terminal installations, install directories, and software versions.
  • Queries winget list (installed version) and winget show (available version) to report both current and latest software versions with a status of UP TO DATE, UPDATE AVAILABLE, NOT INSTALLED, or INSTALLED (not in winget).

MetaTrader 5 detection priority:

  1. Windows registry keys under HKCU/HKLM\SOFTWARE\MetaQuotes\Terminal (fast, ~5 ms)
  2. Well-known install paths (%ProgramFiles%\MetaTrader 5\terminal64.exe, the MetaTrader 5 installation folder under Program Files)
  3. PowerShell Get-Package -Name '*MetaTrader*' (slow fallback)

When an install path is available, the version is read directly from terminal64.exe's FileVersion metadata via PowerShell's VersionInfo property. This gives an authoritative version number even when winget has no record of the installation (typical for MT5, which is often installed outside winget's package database).

2.3 Ecosystem Health Audit (audit)

The audit command executes an exhaustive diagnostic audit of all seven repositories in the ecosystem.

# Full audit with per-project safety classification (~30-90s)
lem-env audit

# Fast audit — skips pip dry-runs
lem-env audit --fast
  • --fast: Flag: None; Type: Bool; Default: False; Description: Skip per-project pip safety dry-runs. Audit completes in seconds but the Safe-↑ column in the drift matrix is left empty.

Diagnostic checks performed:

  • Toolchain prerequisites verification for Python, Git, NPM, and MetaTrader 5.
  • Virtual environment presence, Python executable health, and missing package count for each repository.
  • Node.js workspace health, inspecting package.json, node_modules, and declared dependencies.
  • Manifest Coverage: declared vs installed vs missing vs extra vs platform-skipped counts per project.
  • Python Package Drift & Upgrade Status matrix. Every package declared in two or more manifests appears with:
    • Pin type glyph: = (exact ==), ~ (range), * (floating), · (transitive install), empty (declared but not installed)
    • Upgrade marker: ↑ (safe update available), ⊘ (blocked by reverse dependency), none (at latest version)
  • Packages Declared in Only One Manifest: full inventory of drift-invisible packages.
  • NPM Package Dependency Matrix inspecting declared versus installed package versions.
  • NPM Package Drift Across Workspaces.

Blocked upgrades include a reason string naming the requiring package and constraint, e.g. pylint requires astroid<=4.1.dev0,>=4.0.2.

2.4 Smart Clean Install Pipeline (install)

The install command runs the automated seven-step environment creation and package installation pipeline.

# Execute clean install across all ecosystem projects
lem-env install

# Target a specific repository
lem-env install --project lemgendary-training-suite

# Install without purging existing virtual environments
lem-env install --no-clean
  • --project: Flag: -p; Type: Text; Default: None; Description: Restrict installation to a single target repository
  • --clean / --no-clean: Flag: None; Type: Bool; Default: True; Description: Completely purge existing .venv and node_modules before fresh recreation. The venv currently executing the pipeline is preserved automatically.

The pipeline executes in sequential order:

  1. Hardware discovery and backend acceleration detection.
  2. Global toolchain verification (Python, Git, NPM).
  3. Virtual environment provisioning and purge (skips the running venv).
  4. Python package installation using locked manifests, followed by OpenCV variant normalization.
  5. Node.js package installation via NPM.
  6. Post-install validation (py_compile, lint, YAML, JSON, HTML/WCAG, domain gates).
  7. Final ecosystem health audit generation.

2.5 Safe Bottom-Up Package Upgrades (update)

The update command safely resolves outdated dependencies and upgrades them bottom-up across the dependency hierarchy: lemgendary-env-manager -> lemgendary-datasets -> lemgendary-training-suite -> lemgendary-ai-studio-gui.

# Inspect potential upgrades without modifying files
lem-env update --dry-run

# Apply upgrades and auto-sync requirement manifests
lem-env update
  • --project: Flag: -p; Type: Text; Default: None; Description: Target package upgrades for a specific repository
  • --dry-run: Flag: None; Type: Bool; Default: False; Description: Display proposed version changes without executing installations

Every candidate upgrade passes through a multi-layer safety pipeline before being applied:

  1. Reverse-dependency check: pip inspect --local is used to build a reverse-dependency graph of every installed package. Any candidate whose target version would violate an installed package's requirement is marked BLOCKED with an explanation.
  2. Constraint-preserving dry-run: Every non-target installed package is written into a temporary pip constraints file. If pip cannot resolve the target batch without downgrading or removing anything, the batch is split into per-package checks so a single bad candidate does not poison the whole set.
  3. CUDA-aware torch handling: On CUDA hosts, torch, torchvision, and torchaudio are resolved against the PyTorch CUDA index the probe picks from the driver version (for example download.pytorch.org/whl/cu126). Only packages already installed in the project are considered; packages already at the newest CUDA build produce a VERIFIED event instead of a spurious UPGRADED event.
  4. Snapshot + rollback: Each batch is snapshotted via pip freeze, applied, and verified with pip check. If the check fails, the batch is rolled back from the snapshot.

After all pip/npm upgrades complete, centralized manifests in lemgendary-env-manager/requirements/ are automatically re-written to reflect actual installed versions. Packages in PROTECTED_FROM_SYNC (astroid, pylint, pydantic, pydantic-core) are passed through untouched to prevent a transient upgrade-time drift from being permanently encoded into the manifest.

2.6 Manifest Synchronization (sync)

The sync command captures currently installed packages from active virtual environments and synchronizes pinned requirement manifests under lemgendary-env-manager/requirements/.

lem-env sync

Manifests maintained:

  • requirements-env-manager.txt
  • requirements-datasets.txt
  • requirements-training.txt
  • lemgendary-ai-studio-gui.package.json

This is called automatically by install and update — use directly only when you need to reset a project's requirements without running the full pipeline.

2.7 Multi-Gate Validation Engine (validate)

The validate command enforces strict quality, formatting, compilation, and domain integrity gates across all seven workspaces.

# Validate entire ecosystem
lem-env validate

# Validate specific project
lem-env validate --project lemgendary-docs

Validation gates enforced (in run order, from env_manager/validation/registry.py):

  • Python bytecode: Tool: py_compile; Projects: Python projects
  • Zero-emoji: Tool: Regex scan; Projects: All projects
  • YAML lint: Tool: yamllint (env-manager .venv); Projects: All 7 repos
  • JSON RFC 8259: Tool: Python json (in-process); Projects: All 7 repos
  • Markdown lint: Tool: markdownlint-cli2; Projects: All 7 repos
  • JS/TS linting: Tool: ESLint (--format json); Projects: Node projects (lemgendary-ai-studio-gui)
  • TypeScript types: Tool: tsc --noEmit; Projects: Node projects
  • W3C HTML: Tool: html-validate; Projects: static HTML sites (lemgendary-docs)
  • WCAG 2.2 AA: Tool: pa11y; Projects: static HTML sites (lemgendary-docs)
  • PowerShell analysis: Tool: PSScriptAnalyzer (pwsh preferred); Projects: Repositories with .ps1
  • Pylint: Tool: pylint from the project's .venv with the project's own config; Projects: Python projects
  • Forbidden suppressions: Tool: in-process scan (Python directives and warnings ignore filters, TS/JS @ts-* and eslint-disable comments, Rust allow attributes); Projects: All projects
  • Absolute paths: Tool: in-process scan for hardcoded absolute paths; Projects: All projects
  • Domain Verifications: Tool: domain gates (README changelog, docs sync, docs manifests, docs suite, dataset manifests, training suite, models hub, git hooks); Projects: the matching repositories
  • Ecosystem SSOT: Tool: ecosystem_ssot (error severity): literal ports, Kaggle owner, docs URL or project lists that do not come from lemgendary-env-manager/ecosystem/ecosystem.json; Projects: All projects

Gates fail closed: a missing or crashing tool is a tool_error finding, and the npx fallback (npx --no) never downloads packages. Every gate runs its tool with the project directory as working directory (since LemGendary Environment Manager v16.9.80), so validate gives the same result from the workspace root as from inside a project.

All Node.js validation tools are resolved locally from lemgendary-env-manager/node_modules/.bin via _resolve_tool_cmd(), eliminating global toolchain pollution.

Note on WCAG for the React app (lemgendary-ai-studio-gui): The Vite/React build produces a minimal index.html shell with a single <div id="root">. WCAG accessibility validation of the fully rendered UI requires a running dev server. The validate command runs ESLint and TypeScript checks for the GUI instead; WCAG should be run manually via npx pa11y http://localhost:5173 against a live dev server.

2.8 Workspace Cache & Residue Purge (clean)

The clean command removes volatile temporary files, caches, and build artifacts to maintain absolute workspace hygiene.

# Clean entire workspace
lem-env clean

# Clean specific repository
lem-env clean --project lemgendary-training-suite

Purged items include:

  • __pycache__ directories and .pyc bytecode files.
  • .pytest_cache, .mypy_cache, and .ruff_cache.
  • Temporary build residues (dist/, build/, *.egg-info).
  • Staging artifacts (.staging_*, staging_*, .kaggle-partial, .tmp, .log).

2.9 Telemetry Daemon & Background Server (serve)

The serve command launches the FastAPI REST API and WebSocket real-time telemetry server.

# Start server on default address
lem-env serve

# Start on custom interface and port
lem-env serve --host 0.0.0.0 --port 8000
  • --host: Flag: -h; Type: Text; Default: 127.0.0.1; Description: Network interface address to bind the HTTP listener
  • --port: Flag: -p; Type: Int; Default: 8000; Description: TCP port for incoming REST and WebSocket connections

Server lifecycle is managed via FastAPI's @asynccontextmanager lifespan handler, ensuring the background event-drain task is cancelled cleanly on shutdown.

2.10 Git Hook Installation (setup-hooks)

The setup-hooks command (with canonical alias hooks) installs or repairs standardized pre-commit hooks across all ecosystem projects.

# Install hooks across all projects
lem-env setup-hooks
# Or using the concise alias:
lem-env hooks

# Install for a single project
lem-env setup-hooks --project lemgendary-datasets

The installed hook delegates validation to lem-env validate --project <name> and blocks the commit if any gate fails. This ensures every repository runs the same validation pipeline regardless of local toolchain state.

3. Interactive PowerShell Host (lemgendary_env_manager.ps1)

For Windows terminal operators, lemgendary_env_manager.ps1 provides an interactive, keyboard-driven management console.

Execution syntax:

powershell -ExecutionPolicy Bypass -File .\lemgendary_env_manager.ps1

Interactive Menu Matrix:

  • [1] Probe System & Hardware Accelerators: Executes hardware discovery and checks for updates.
  • [2] Run Full Ecosystem Health Audit: Displays toolchain, virtual environment, manifest coverage, drift matrix, single-manifest inventory, and NPM dependency matrix.
  • [3] Execute Smart Clean Install Pipeline: Purges environments and installs clean dependencies.
  • [4] Run Safe Package Updates: Executes bottom-up dependency upgrades and syncs manifests.
  • [5] Validate Projects: Enforces py_compile, ESLint, YAML, JSON, W3C, WCAG 2.2 AA, and domain gates.
  • [6] Start/Stop Background API Server: Launches or stops the FastAPI server as a background PowerShell job with live WebSocket streaming.
  • [Q] Quit: Gracefully terminates the management console.

5. Datasets Compilation Suite CLI

The lemgendary-datasets repository provides the unified lemgendary CLI (cli.py), exposing a full suite of compiler, synthesis, audit, transcoding, and server operations. All commands feature transparent hybrid routing: when the sidecar API daemon is active on 127.0.0.1:8100, commands submit tasks to the API and render live WebSocket logs to Rich Console; when stopped or when --no-server is passed, commands fall back cleanly to direct in-process execution.

5.2 Manifold Compilation (compile)

Compiles raw image and market data into production-ready dataset manifolds with optional multi-container emission and quality gates:

# Standard compilation with default WebP q=92
python cli.py compile --model nima_aesthetic --max-gb 50

# Compile using canonical compiler preset (Phase 8)
python cli.py compile --model nima_aesthetic --preset quality-vision

# Concurrently emit WebP directory and a LitData container
python cli.py compile --model nima_aesthetic --image-format webp \
  --image-quality 92 --also-format litdata

# High-throughput compile bypassing aesthetic vetting and labeling
python cli.py compile --model nafnet_deblurring --workers 16 --no-vetting --no-labeling

# Force container byte duplication across hardlink gates
python cli.py compile --model upn_v2 --also-format litdata --force-duplicate

# Force in-process compilation bypassing active API server
python cli.py compile --model nima_technical --no-server
  • --model, -m: Type: String; Default: None; Description: Dataset registry key in unified_data.yaml
  • --preset, -p: Type: String; Default: None; Description: Predefined compiler preset profile (quality-vision, restoration-hardlinked, detection-variable, cloud-archival)
  • --max-gb: Type: Float; Default: Config; Description: Maximum size allocation threshold in gigabytes
  • --workers: Type: Integer; Default: Auto; Description: Number of parallel worker threads/processes
  • --image-format: Type: String; Default: webp; Description: Target format: webp, jpeg, png, keep
  • --image-quality: Type: Integer; Default: 92; Description: Target image compression quality (1-100)
  • --target-quality: Type: Integer; Default: 95; Description: Restoration target ground-truth quality
  • --mask-format: Type: String; Default: webp-lossless; Description: Segmentation mask format
  • --also-format: Type: String; Default: None; Description: Comma-separated containers: litdata, wds, parquet; mds needs the optional mosaicml-streaming package, which the Environment Manager no longer installs (MDS compilation is discontinued since Environment Manager v16.9.81)
  • --no-vetting: Type: Flag; Default: False; Description: Bypass NIMA aesthetic score gate
  • --no-labeling: Type: Flag; Default: False; Description: Bypass YOLO detection auto-labeling
  • --no-hash: Type: Flag; Default: False; Description: Bypass pHash/dHash perceptual deduplication
  • --no-server: Type: Flag; Default: False; Description: Force local in-process execution

5.3 Degradation Engine Synthesis (degrade)

Derives paired synthetic restoration manifolds from clean ground-truth sources using mathematical physical kernels:

# Motion blur and heteroscedastic sensor noise synthesis
python cli.py degrade --source raw-sets/div2k \
  --output LemGendizedNafNetDebluringSynthetic --profile motion-blur+iso-noise

# Atmospheric haze synthesis on custom manifold directory
python cli.py degrade --source ../LemGendaryDatasets/LemGendizedNimaAesthetic \

# Dry-run validation
python cli.py degrade --source raw-sets/div2k --output LemGendizedTest \

  • --source, -s: Type: String; Default: Required; Description: Source dataset folder or registered manifold name
  • --output, -o: Type: String; Default: Required; Description: Destination synthetic manifold folder name
  • --profile, -p: Type: String; Default: motion-blur+iso-noise; Description: Profile token or composite expression
  • --intensity: Type: String; Default: medium; Description: Intensity preset: low, medium, high
  • --pairs: Type: Integer; Default: None; Description: Maximum sample pair count cap
  • --val-split: Type: Float; Default: 0.12; Description: Validation set split ratio
  • --seed: Type: Integer; Default: 42; Description: Deterministic random number seed
  • --image-format: Type: String; Default: webp; Description: Target output format for degraded images
  • --dry-run: Type: Flag; Default: False; Description: Simulate derivation plan without writing files

5.10 Cloud & Metadata Sync (sync, docs, config)

# Kaggle dataset push and pull
python cli.py sync push --model nima_aesthetic
python cli.py sync pull --url lemgenda/lemgendizednimaaesthetic

# Fetch only some folders or files (repeatable --only), into another folder
python cli.py sync pull --url lemtreursi/lemgendizedretinafacemobilenetlarge \
  --only labels/ --only classes.txt --output RetinaFaceLabels

# Update Kaggle metadata across all manifolds or a single manifold
python cli.py sync metadata --all
python cli.py sync metadata --model nima_aesthetic

# Documentation regeneration
python cli.py docs regen

# Schema validation
python cli.py config validate

sync pull creates the datasets root (LemGendaryDatasets/) when it is missing and measures free space at the nearest existing parent folder. When Kaggle has no whole-dataset archive (HTTP 404 "No gcs url found") the pull falls back to a file-by-file download: every page of the file listing is read, each file is fetched through its signed URL, checked against the listed size and skipped on a re-run, and an interrupted .part resumes with an HTTP range. After the first per-file 404 the Kaggle API's dataset_download_file serves every remaining file. HTTP 429 waits and retries on both routes (Retry-After, else 30 s doubling up to 600 s). --only fetches a folder (ending in /) or file relative to the dataset's top folder, from the zip through HTTP byte ranges or file by file. A pulled registered manifold packs its text labels into JSON with the entry's label strategy. A new Kaggle dataset is created private; the metadata push applies the registry is_private and license.

5.13 Direct Streaming Zip-to-Container Engine (stream_zip_to_container.py)

Directly streams multi-gigabyte legacy dataset zip archives into canonical POSIX WebDataset .tar shards with on-the-fly 12-thread WebP transcoding, eliminating NTFS MFT file allocation overhead and real-time antivirus filter driver slowdowns:

# Stream paired restoration dataset directly to WebDataset shards with WebP transcoding
python tools/stream_zip_to_container.py \
    --zip ../LemGendaryDatasets/lemgendizedmirnetexposure.zip \
    --target ../LemGendaryDatasets/LemGendizedMirNetExposure \
    --shard-size 5000 \
    --delete-zip

# Stream split target dataset (UpnV2) with automatic metadata and index.json extraction
python tools/stream_zip_to_container.py \
    --zip ../LemGendaryDatasets/lemgendizedupnv2.zip \
    --target ../LemGendaryDatasets/LemGendizedUpnV2 \
    --shard-size 5000 \
    --delete-zip
  • --zip: Type: Path; Default: Required; Description: Path to the source multi-gigabyte .zip archive
  • --target: Type: Path; Default: Required; Description: Destination modernized manifold directory
  • --format: Type: Choice; Default: webdataset; Description: Target container format (webdataset)

5.17 Manifold Repair (repair)

Repairs a compiled manifold in place without a recompile. Every subcommand is a dry run that prints its plan unless --apply is given, takes --model KEY (registry key) or --manifold PATH, rewrites each changed shard to a temporary file, verifies it and swaps it in atomically (no backup copies are kept), and keeps index.json and the dataset_info.yaml count in step. A re-run finds nothing to do. Every subcommand that rewrites shards also refreshes the shard_offsets.json index of each shard folder it touched (dataset compiler v16.9.108).

# Zero-byte samples, scattered groups, png/jpg members, counts, paths
python cli.py repair manifold --model retinaface_mobilenet
python cli.py repair all

# Labels from a loose labels/<split>/<key>.txt folder into the JSON labels
python cli.py repair labels --model retinaface_mobilenet \
  --labels ../LemGendaryDatasets/_labels/RetinaFace/labels --apply

# Legacy .txt label members merged into <key>.json, then removed
python cli.py repair txt-labels --model yolov8n --apply

# Loose images/ + labels/ folders packed into JSON-labelled WebDataset shards
python cli.py repair pack-loose --model yolov8n --apply

# Registry sample policy: drop copies, auxiliary images and no-face samples,
# re-split val by source file id
python cli.py repair sample-policy --model retinaface_mobilenet --apply

# ParseNet class masks from the SFHQ segmentations/ folders
python cli.py repair masks --model parsenet --masks-root ../sfhq --apply

# RetinaFace boxes and 5 points rebuilt from the SFHQ 110-point landmarks
python cli.py repair face-landmarks --model retinaface_mobilenet \
  --landmarks-root ../sfhq --apply

# ClassificationMaster: pseudo-label table first, then the class labels
python cli.py repair pseudo-labels --model classification_master_manifold \
  --table-root ../LemGendaryDatasets/_labels/LemGendizedClassificationMaster
python cli.py repair class-labels --model classification_master_manifold \
  --table-root ../LemGendaryDatasets/_labels/LemGendizedClassificationMaster \
  --apply

# Shard offset index (shard_offsets.json) of every shard folder; the shards
# are not changed
python cli.py repair shard-offsets --model upn_v2
python cli.py repair shard-offsets --model upn_v2 --apply
  • manifold, all: Description: Zero-byte samples, scattered sample groups, leftover PNG/JPEG members (re-encoded to WebP with the compiler's encoders), counts and recorded paths. A present shard_offsets.json is verified, and a stale one is rewritten on --apply.
  • labels: Options: --labels DIR (required), --strategy NAME, --classes FILE; Description: Writes each sample's label from DIR/<split>/<key>.txt into its JSON label through the registry label_json strategy. A label whose boxes differ from the recorded ones is a MISMATCH and refuses the apply.
  • txt-labels: Options: --strategy NAME; Description: Merges every .txt label member into the sample's JSON (keys must agree; nothing is dropped) and removes the .txt members. MISMATCH or UNREADABLE labels refuse the apply.
  • pack-loose: Options: --strategy NAME; Description: Packs images/<split> + labels/<split> into shards/<split>/shard-*.data with <key>.webp + <key>.json. Refuses while an image has no label file, a label has no image or shards already exist; removes the loose folders only after the packed shards verify.
  • sample-policy: Description: Applies the registry sample policy (face detection: drop no-face samples and copies, val drawn from the landmark-bearing photos by source file id; face parsing: drop copies and segmentation maps, split all photos by source file id).
  • masks: Options: --masks-root DIR (required), --workers N; Description: Stores each photo's source class mask as lossless <key>.mask.webp (class ids checked after a decode round trip) and records num_classes, class_names and mask_source in the JSON label.
  • face-landmarks: Options: --landmarks-root DIR (required), --workers N; Description: Replaces each photo's objects with one face: a tight WIDER-style box and five points derived from the source landmark file, landmark_source recorded. A sample that fails the plausibility check is dropped; a missing landmark file refuses the apply.
  • pseudo-labels: Options: --table-root DIR (required), --workers N, --max-shards N; Description: Runs the registry pseudo-label models (ONNX, CPU) over the pseudo-rule samples and writes one JSON Lines table per shard outside the manifold; the shards are not touched, and a re-run resumes.
  • class-labels: Options: --table-root DIR (required), --workers N; Description: Writes class_id, class_name, label_source and the registry task into each sample's JSON (pseudo labels also label_confidence and label_check_class); a pseudo label that fails its rule drops the sample, and a sample without a rule or table row refuses the apply.
  • shard-offsets: Options: --model KEY or --manifold PATH, --apply; Description: Writes the Shard Offset Index shards/<split>/shard_offsets.json (format version 2) without touching the shards. The dry run reports each shard folder's index as missing, stale (with the reasons) or current, checking a present index the way the Training Suite does: an entry is accepted when the shard size matches and either the modification time matches or the tar headers of the first, middle and last member agree. --apply keeps the entries of unchanged shards, rescans the rest, prints the file size and time, and exits 1 when a folder is still not current afterwards. Compressed shards get no entry. See Section 4.13 of the Dataset Compiler paper.

6.13 Kaggle Cloud Training How-To (lemtrain kaggle)

A Kaggle training session is a private notebook kernel that the Training Suite builds from the same generator as the notebook files (lemtrain kaggle bundle), pushes with the Kaggle API (lemtrain kaggle launch, the GUI or POST /api/training/kaggle/train) and watches until it ends. Run the commands from the lemgendary-training-suite root.

1. Kaggle API Token

Kaggle API tokens start with KGAT_. The suite resolves one credential (training/cloud/credentials.py) in this order: the .secrets.yaml vault of the Environment Manager (default Kaggle record), the environment (KAGGLE_API_TOKEN, then a legacy KAGGLE_KEY with KAGGLE_USERNAME), ~/.kaggle/kaggle.json, then ~/.kaggle/access_token (or access_token.txt). A KGAT_ token is exported unchanged as KAGGLE_API_TOKEN, the name kaggle 2.x, kagglesdk and kagglehub read first; it never goes into kaggle.json as a legacy key (the CLI answers 401). The Environment Manager writes a vault token to ~/.kaggle/access_token. The legacy .kaggle_users and .kaggle_token files are no longer read.

# Check that the resolved credential really works (one authenticated call)
curl -s http://127.0.0.1:8200/api/training/kaggle/status

2. Kaggle Secrets of the Kernel

Attach these secrets to the kernel (Kaggle notebook editor, Add-ons, Secrets) before the first launch. The secrets cell reads them with kaggle_secrets.UserSecretsClient (Colab: google.colab.userdata):

  • KAGGLE_API_TOKEN: Required; a KGAT_ token. Exported for the Hub sync and the resume pull; a legacy key is refused. KAGGLE_KEY and KAGGLE_USERNAME secrets are no longer read.
  • GITHUB_PAT or SUITE_PAT: Required while the suite or env-manager repository is private. The clone gets it only through GIT_ASKPASS, never in a URL or a file.
  • GOOGLE_DRIVE: Optional; Google Drive mirroring.

Without KAGGLE_API_TOKEN the session trains but cannot read or write the Kaggle Models Hub ([AUTH] Secrets available: [] in the log).

3. Accelerators

The accelerator table lives in the ecosystem file (lemgendary-env-manager/ecosystem/ecosystem.json, section kaggle); retired machine shapes (P100, the older TPU shapes) are never offered:

  • cpu: CPU; no machine shape.
  • gpu-t4x2: GPU T4 x2 (NvidiaTeslaT4); the default.
  • tpu-v5e8: TPU v5e-8 (TpuV5E8).
lemtrain kaggle accelerators

4. Bundle, Launch and Status

# Write the kernel bundle (notebook + kernel-metadata.json) for review
lemtrain kaggle bundle upn_v2 --out ../kaggle_bundle

# Push the kernel and start the session
lemtrain kaggle launch upn_v2 --accelerator gpu-t4x2

# Test fix-branch code for 45 minutes, stopping 5 minutes before the limit
lemtrain kaggle launch upn_v2 --git-ref fix/review-remediation \
  --limit-hours 0.75 --margin-minutes 5

# Session status (QUEUED, RUNNING, COMPLETE, ERROR, CANCEL_REQUESTED, ...)
lemtrain kaggle status upn_v2

The kernel id is <user>/<registry slug>-training; the bundle is private with internet on and mounts the model's manifold datasets and, when the Hub has one, the latest pytorch/default version (--resume-version N pins another). The same options exist on python -m training.kaggle_cloud_manager --action launch and, as JSON fields, on POST /api/training/kaggle/train:

  • --git-ref: Branch, tag or full commit SHA the kernel clones the suite at (default main). Letters, digits, ., _, / and - only, a letter or digit first, at most 200 characters; the clone prints [GIT] <url> at <ref> (<sha>).
  • --env-manager-ref: Ref of the env-manager clone (default: the --git-ref value).
  • --limit-hours: Session limit for this kernel (default kaggle_session.limit_hours of config.yaml, 12).
  • --margin-minutes: Minutes before the limit the trainer stops (default kaggle_session.margin_minutes, 30).
  • --override-frozen: Resume although a frozen run setting changed (logged and recorded in settings_changes.jsonl); also used by the auto-resume sessions of a GUI job.

5. Session Guard, Deadline Stop and Auto-Resume

  • 12 h session guard: the first cell exports LEMGENDARY_SESSION_START; the training and validation loops check the deadline (limit minus margin) every step and before each epoch. Under DDP the ranks agree every 25 steps, so no rank stops alone.
  • Deadline stop: at the deadline the loop saves progress.pth (generator states included), writes LemGendaryModels/<model>/session_deadline.json, runs the final Hub sync, prints [DEADLINE] and exits 0. No release export runs.
  • Auto-resume: a GUI or API job launched with auto_resume: true (default kaggle_session.auto_resume, false) reads the marker from the kernel output and pushes a new kernel version that resumes from the Hub, at most max_resumes times (default 3). lemtrain kaggle launch starts one session and does not watch it.
  • Publish gate: the training cell ends with training.cloud.trainer_exit.check_trainer_exit. A non-zero trainer exit raises TrainerExitError, the kernel ends with ERROR and no later cell (release publish, Google Drive mirror) runs. Exit 0 with session_deadline.json is the resumable deadline stop; the publish cell skips itself on the marker.
  • Resume refusal record: a resume refused because a frozen setting changed writes LemGendaryModels/<model>/resume_refusal.json (the FrozenSettingsChanged text and the changed setting names). The Kaggle job then fails with that text as its error_message, the same text a local job records. Relaunch with --override-frozen or start fresh.

6. Kaggle Models Hub Variations and Push Policy

VariationKey (training/cloud/variations.py) is the single list of Hub variations: pytorch/default (checkpoints, README.md, metrics.csv), pytorch/fp32 (<Stem>.pt), onnx/fp16 (<Stem>.onnx) and onnx/fp32 (<Stem>_FP32.onnx + .onnx.data). --variation and the API variation take one of them or all; the old names (pytorch, onnx_fp16) are refused.

One push policy (KaggleModelSyncManager.push_model) serves the GUI, lemtrain sync push, kaggle_cloud_manager and the notebook release: validate the key, stage dist/kaggle, create or update the model page before the first upload (a failed page sync uploads nothing), upload each variation with the license from the model metadata, then sync the metadata again. A variation whose staged files have the same SHA-256 as its last upload (recorded in <model>/.kaggle_sync.json) is skipped: no new Hub version, UNCHANGED in the log. The per-epoch auto-sync uploads only pytorch/default, every fleet.kaggle_sync_every_epochs epochs (default 5) and on a new best (fleet.kaggle_sync_on_best).

Every upload carries version notes with the stored epoch, up to six measured values of the last metrics.csv row and the suite version, for example Release: mirnet_exposure [ONNX FP16] | epoch 41 | val_loss=0.0123 psnr=27.1000 | suite v16.9.177.

7. First Live Check

  1. Attach KAGGLE_API_TOKEN and GITHUB_PAT to the kernel.
  2. lemtrain kaggle bundle upn_v2 --out <folder> and review kernel-metadata.json.
  3. lemtrain kaggle launch upn_v2 --accelerator gpu-t4x2 --limit-hours 0.2 --margin-minutes 5.
  4. Expect [AUTH] Secrets available with both secrets, checkpoints under /kaggle/working/LemGendaryModels/<model>/checkpoints/, [DEADLINE] and session_deadline.json in the output, COMPLETE from lemtrain kaggle status upn_v2 and Hub version notes with the epoch and suite version.
  5. Launch again: the session resumes from the Hub. A second push of unchanged files reports every variation as UNCHANGED.

9. Exit Codes, Automation & CI/CD Integration

All ecosystem CLI tools follow standard POSIX and Windows process exit code conventions:

  • 0: Meaning: Success; Operator Action: Operation completed successfully with zero violations or errors
  • 1: Meaning: General Failure; Operator Action: Unhandled exception or syntax failure during execution
  • 2: Meaning: Validation Error; Operator Action: One or more quality, linting, or domain gates failed verification
  • 3: Meaning: Missing Prerequisites; Operator Action: Required toolchain component (Python, Git, NPM) is not installed
  • 4: Meaning: Network / IO Error; Operator Action: Failed to reach remote registry or download necessary assets

Continuous Integration Workflow Example:

# Standard CI/CD verification pipeline
lem-env audit --fast || exit 1
lem-env validate || exit 2
