1. Abstract

The LemGendary Model Training Suite is the orchestration layer that trains, evaluates and exports the vision, restoration, quality-assessment, financial time-series and causal LLM models of the LemGendary ecosystem. This paper documents release v16.9.157-STABLE. It covers the curriculum governor and its Monotonic Ratchet (pair rule, enforced by a RatchetViolation guard), the bounded epoch budget with an honoured early stop, the 4-pillar completion invariant, publication-grade FID evaluation (feature=2048, chunks of at most two samples), the Pareto Model Soup service, optional Stochastic Weight Averaging (SWA, off by default, Section 2.32) and the sidecar security model. Features that earlier revisions described but the code does not run are marked as not active or not implemented (Section 8.1). Historical FID rows of four models are unverified (Section 2.28); the FID re-evaluation tool (Section 2.33) can re-measure their checkpoints. Releases v16.9.140 to v16.9.157 decode container targets for every task, resume mid-epoch deterministically, read shards by byte offset, score restoration models with one quality formula ($\text{PSNR} + 20 \cdot \text{SSIM} - 20 \cdot \text{LPIPS}$, FID as a separate gate) and keep the effective batch exact across resolution jumps (Sections 2.36 to 2.39).

2. High-Fidelity "Nuclear" Hardening

The suite enforces a strict high-fidelity baseline to ensure models learn complex textures and micro-artifacts from the very first epoch.

2.1. Dynamic Memory-Sentinel (Batch Decoupling)

  • Absolute Sentinel Authority: Acts as the absolute physical authority. It treats batch_size from config as a maximum boundary and autonomously throttles it downwards if the local physical VRAM cannot hold it, permanently preventing system RAM paging.
  • Atomic Re-Audit: Performs a fresh hardware probe every time the resolution ladder jumps, ensuring peak physical throughput at low resolutions while automatically throttling for high-res stability.
  • Sub-Nuclear 4GB Lockdown: On GTX 1650/4GB cards, it enforces a strict Serial-Only Mode after an OOM, delivering a 2x performance gain by preventing Windows System RAM paging.
  • Hardware-Aware Resolution Capping (not active): config.yaml declares max_allowed_local_resolution: 640 and max_allowed_cloud_resolution: 512, but the training code does not read these keys (review finding D-07), so they do not cap the ladder. The governor only clamps the configured input_size to the hardware cap before training starts.
  • Worker Lifecycle Graceful Shutdown & GC Teardown: Explicitly reaps training DataLoader iterator processes (persistent_workers=False), caps workers, and injects gc.collect() and torch.cuda.empty_cache() teardown sequences before spawning the validation pipeline. This eliminates System RAM hoarding and extreme VRAM fragmentation, stabilizing high-resolution validation on Kaggle kernels (T4/P100).
  • Multi-GPU DataParallel Gathering Safeguard: Automatically detects multiple CUDA devices and wraps the active manifold in PyTorch's DataParallel engine. Fixes primary-device VRAM bottlenecking by eliminating naive gpu_count micro-batch multiplication at high resolutions ($\ge 512\text{px}$) and for restoration architectures. GPU 0 is protected from output gathering saturation and loss graph spikes, utilizing Universal Gradient Accumulation to maintain the target effective batch size.
  • Dynamic Headroom Tiering & Pre-Jump Dry-Run Probe: Enforces a 30% free VRAM safety headroom margin (safety_multiplier = 0.70) for spatial ladders $\ge 512\text{px}$ and perceptual loss engines (LPIPS/VGG). Not active: the pre-jump dry-run probe and the resolution-jump veto (MemorySentinel.veto_resolution_jump, SmartTrainingGovernor.veto_resolution_jump) have no caller in the training loop. Since v16.9.67 the governor veto can only anchor at or above the current resolution, so it can never lower the resolution once it is wired in.
  • Hardware ECC, CUDA Kernel Compatibility & Virtual Memory Fragmentation Guard: Detects uncorrectable ECC hardware errors and CUDA compute kernel incompatibilities (such as Pascal sm_60 on modern CUDA 12 builds) during pre-flight sanity checks with clear diagnostic recovery guidance and auto-remediation, and configures PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True to eliminate CUDA memory allocator fragmentation.
  • Validation Coverage (no sharding): No validation sharding is implemented. The code reads no high_fidelity_fraction key, so the 30% validation shard with auto-expansion described in earlier revisions is not in effect. Financial Time-Series & Forex Predictors evaluate 100% of the validation manifold every epoch for Walk-Forward temporal progression matrices.
  • Windows Memory-Mapped Sequence Multiprocessing Guard: PyTorch DataLoader with num_workers > 0 on Windows uses multiprocessing.spawn, duplicating dataset indices and memory-mapped file handles into each worker process (consuming 20+ GB across 4 workers). For large time-series manifolds (e.g. 16-symbol Forex), the suite strictly enforces num_workers = 0 on Windows, keeping total process RAM at 1.1 GB, eliminating 50GB+ pagefile thrashing, and keeping .npy arrays cached in the OS file cache for $12.5\times$ faster batch throughput (0.27s vs 3.43s).

2.2. Intelligent Curriculum & Sawtooth Governance

  • Universal Monotonic Progression Ratchet (pair rule): The curriculum moves through (resolution, data fraction) rungs and never steps backwards (Section 2.25). Resolution never decreases. Within one resolution step the data fraction never decreases ($f_{t+1} = \max(f_t, f_{\text{new}})$). The fraction may reset to a lower value only when the resolution steps up. Resumed sessions on cloud environments (e.g. Kaggle/Colab) retain the highest fraction recorded in metrics.csv. Data fraction strides are 20% (fraction_increment: 0.20).
  • Publication-Standard FID 2048 & Micro-Chunked Memory Isolation: The validation subsystem computes Frechet Inception Distance on the 2048-dimensional final pooling layer (feature=2048). Inception forward passes run in micro-chunks of at most two samples (chunk_size = 2) for both real and reconstructed images (Section 2.28). The historical FID rows of codeformer, ffanet_indoor, mprnet_deraining and mirnet_lowlight were rewritten by the removed tools/recalibrate_fid.py and are unverified; python -m training.fid_reeval re-measures them (Section 2.33).
  • Pareto Model Soup (vault checkpoint blending): lemtrain soup and POST /api/models/{model_key}/soup blend a model's vault checkpoints (vault_psnr.pth, vault_lpips.pth, ...) into one weighted average checkpoint (Section 2.27). With optional Stochastic Weight Averaging (Section 2.32) the averaged weights are one more vault, vault_swa.pth. Whether a blend beats its donors is not checked automatically and must be measured per model.
  • Universal Quality Scorecarding: Restoration, enhancement and face models are scored with PSNR, SSIM and LPIPS on every epoch; FID is a separate publication gate checked against the SOTA targets (Section 2.38).
  • Continuous Parameter Predictor Calibration: Standardized validation MAE telemetry for continuous parameter predictors (like upn_v2), recording MAE directly into metrics.csv.
  • Professional Multi-Task Restoration: Fully integrated multi-headed Mixture-of-Experts (MoE) routing engine with 11 specialized restoration heads dynamically trained under Dynamic Filename Task Ingestion.

2.3. Hardened Resolution Ladders & SOTA Guards

  • Universal 15% Initial Manifold Fraction: All model training pipelines initiate training from 15% dataset fraction ($0.15$) on the lowest ladder rung (res_ladder[0]), progressing through gradual intra-resolution expansion ($15\% \to 35\% \to 55\% \to 75\% \to 100\%$) governed by maturity soak windows (maturity_soak: 5 in config.yaml), performance plateaus, and overfitting indicators.
  • Steady-Improvement Soak Propulsion (v16.9.43): Prevents steadily improving models from stagnating at $15\%$ data fraction when validation quality increases every epoch ($\Delta q \ge \text{min\_delta}$). Once epochs_since_step >= manifold_maturity (default 3 epochs) with non-regressing quality, fraction_soak_complete automatically advances current_fraction by $+20\%$ (fraction_increment = 0.20), and deepening_ready promotes spatial resolution once $100\%$ data fraction and stride_threshold are satisfied.
  • Bounded Epoch Budget: The configured epoch count is a hard cap. Training stops on convergence (4-pillar completion), on the governor's early-stop signal, or when the budget is reached. Budget extensions are opt-in through training_budget.max_extension_epochs (Section 2.26). The open-ended loop of earlier revisions, which added 10 epochs whenever the budget was reached, was removed in v16.9.65.
  • Ladder-Aware Progression: Reaching SOTA targets at sub-maximal resolutions triggers a Forced Spatial Jump to the next rung (e.g., 256px → 384px). The dataset fraction then starts again at a lower value (the configured initial fraction after a regular jump, 50% after a forced SOTA jump). The pair rule allows this reset because the resolution steps up.
  • SOTA Hardening Guard: Enforces a mandatory 2-epoch "Hardening Period" for every resolution rung to solidify weights.
  • Overfitting Rescue Protocol: Overrides tactical recoils and cooldown locks when trend-based overfitting is diagnosed, force-expanding the dataset fraction (+20% data) to break the overfitting attractor.
  • SOTA Verification: Verifies SOTA targets on 100% of training data at final resolution before permitting export.

2.3.1. Authoritative 4-Pillar Fully-Trained Verification Invariant

The training engine and GUI telemetry enforce an absolute, non-negotiable invariant before designating any model as FULLY TRAINED:

$$\text{FullyTrained} = \left(\bigwedge_{m \in \mathcal{M}_{\text{target}}} \text{Passed}(m, T_m)\right) \land (\text{LadderPassed}) \land (\text{DataFraction} \ge 1.0) \land (\text{Epochs} \ge 20)$$
  1. Pillar 1: Multi-Metric SOTA Target Satisfaction ($100\%$):
    • The engine validates every single metric defined in the model's sota_targets dictionary within unified_models_v2.yaml.
    • Directionality is strictly enforced: higher-is-better metrics ($\text{PSNR}$, $\text{SSIM}$, $\text{SRCC}$, $\text{PLCC}$, $\text{Accuracy}$, $\text{mAP50}$, $\text{DirAcc}$, $\text{WinRate}$, $\text{Sharpe}$, $\text{Sortino}$) must satisfy $\text{Achieved} \ge \text{Target}$; lower-is-better metrics ($\text{LPIPS}$, $\text{FID}$, $\text{MAE}$, $\text{MaxDD}$, $\text{TP\_MAE}$, $\text{SL\_MAE}$, $\text{Rank\_Margin}$) must satisfy $\text{Achieved} \le \text{Target}$.
    • If even one defined metric fails to meet its target, SOTA is not achieved ($\text{sota\_targets\_met} < \text{sota\_targets\_total}$).
  2. Pillar 2: Complete Resolution / Confluence / Context Ladder Traversal:
    • Vision Models: Model must have completed training at or above the highest rung in res_ladder ($\text{max\_res} \ge \text{target\_res}$, typically $512\text{px}$ or $640\text{px}$). Reaching SOTA at $256\text{px}$ does not qualify as fully trained.
    • Forex Models: Model must have completed all 6 walk-forward curriculum folds or trained through the macro daily confluence horizon ($\text{Fold} \ge 6 \lor \text{Horizon} \ge 1440\text{m}$).
    • Causal LLM Assistants: Model must operate on its maximum target context token window ($\text{seq\_length} \ge 2048\text{ tokens}$).
  3. Pillar 3: 100% Dataset Variety ($1.00$ Data Fraction / Full Corpus):
    • Vision Models: The model must have completed its epoch on $100\%$ of the training dataset manifold ($\text{Data} \ge 0.99$). Models trained on sub-unitary fractions ($15\%$, $35\%$, $75\%$) are strictly designated as PARTIALLY TRAINED.
    • Causal LLM Assistants: Model must have trained across the complete instruction tuning manifold without loose image sampling fraction constraints.
  4. Pillar 4: Minimum Epoch Convergence Threshold ($\text{Epochs} \ge 20$):
    • The model must have trained for at least 20 epochs ($\text{completed\_epochs} \ge 20$). Rapid early convergence spikes or premature training termination before 20 epochs strictly prohibit declaring training complete.

The resolution and data pillars read the governor state recorded before the epoch audit, through the keys that get_state() writes (input_size, sample_fraction; shared constants in training/ratchet.py, v16.9.67). A missing key counts as 0 and can never pass. A 384px epoch that triggers a jump to 512px is therefore no longer reported as complete.

2.4. Checkpoint Resumption & Singularity Hardening

  • Recovered Governor Topology Synchronization: When restoring from a checkpoint, the engine (training/core_loop.py) directly reconfigures the active dataset strategy (train_ds.update_strategy / sample_fraction) and rebuilds the active DataLoader worker processes (rebuild_train_loader) to match the exact recovered ladder rung and dataset fraction.
  • Unified Hub Checkpoints: Completely obsoletes volatile local checkpoint directories. All models, whether training locally or on Kaggle, directly sync _latest, _best, _progress, and _vault_ checkpoints exclusively to their respective LemGendaryModels/<model_name>/checkpoints vault.
  • Safe Non-Destructive Export Instantiation: Replaced legacy shutil.rmtree overarching folder wipes with precise, non-destructive os.makedirs(exist_ok=True) logic, structurally preventing catastrophic deletion of trained physical model checkpoints across projects.
  • The Scheduler Shield: Dynamically inspects candidate checkpoints for poisoned/advanced step counts. If detected, it overrides and re-anchors the loaded scheduler steps back to actual epoch progress.
  • Velocity Bomb Prevention (Rollback Isolation): During a SOTA Rollback, the Governor surgically decouples the model weights from the learning rate chronometer. It reverts the weights to the safe baseline but intentionally bypasses chronological scheduler rewinding. This prevents the learning rate from violently spiking back to early-stage max_lr values, ensuring the model gently seats into a cold, stable manifold.
  • Metric Singularity & Live Polarity Shield: The Metric Singularity Shield triggers a tactical recoil and rollback to SOTA weights immediately if PLCC/SRCC hit NaN. New in v1.2.2: The Live Polarity Shield monitors the manifold directly during training; if SRCC < 0.0 or PLCC < 0.0 is detected mid-epoch, it immediately flags a "Polarity Collapse", rejecting the epoch and triggering an instant SOTA rollback to purge inverted weights.
  • Absolute Anti-Loop Guard (Dead Man's Switch) (not implemented): Earlier revisions described an absolute_patience limit (15 epochs) that severs the loop and forces a hard SOTA rollback. The current code has no such limit. A stalled run ends through the bounded epoch budget (Section 2.26).
  • Model-Aware Adaptive Loop-Breaker & Loop Guards (v16.3.2) (not active): The breakout logic (spatial resolution promotion, drift-gate relaxation and the breakout_lock shield) exists, but SmartTrainingGovernor.register_rollback has no caller in the training loop (review finding D-10), so it never runs. If it is wired in, the breakout goes through _commit_rung and can only promote the resolution.
  • Autonomous Resolution Escalation & Dynamic Limits (v16.3.3) (not active): The escalation to the next rung in res_ladder (256px -> 384px, fraction reset to 15%) and the relaxed get_active_regression_limit() both depend on rollback registration, which is never invoked (see above).
  • Proven-Manifold Protection (hold and cool): When validation quality regresses, the manifold turns turbulent or collapses, the governor never retreats resolution or data fraction. It holds the current rung, multiplies the learning rate by cooling_factor (default 0.5), sets the stabilization lock and starts a 5-epoch cooldown. The intra-resolution data recoil of earlier revisions (e.g. 75% -> 55% at 512px) is removed because it broke the Monotonic Ratchet.
  • Atomic Governor Fraction Expansion Persistence & Checkpoint State Flush (v16.3.4): Solves cloud session preemption rollback during dynamic dataset fraction expansion. When the SOTA Guard triggers sample fraction promotion (e.g. 75% -> 90% -> 100%), the engine immediately updates the active DataLoader topology, flushes governor.get_state() into the checkpoint payload, and overwrites both _latest.pth and _best.pth on disk. Hub Lock skip-paths are anchored directly to live governor telemetry, guaranteeing that cloud restarts resume precisely at the expanded manifold fraction rather than reverting to pre-expansion checkpoints.
  • ONNX Trace Resilience (FakeTensor Guards): Dynamically wraps unmapped FakeTensor memory pointer access (data_ptr()) during FX/ONNX graph tracing within the DataParallel multi-GPU engine to prevent false-positive segmentation faults during structural graph export.
  • Clean Training Initialization (--clean / --fresh): Operators can trigger pristine training starts via the --clean / --fresh flag, which instructs Hub Sync to bypass git lfs pull, purges existing local checkpoints and locks, resets curriculum_state.json, and wipes metrics.csv to begin strictly from epoch 1.
  • Restored Fraction Is Kept (v16.9.67): A checkpoint's saved data fraction is restored as-is. The earlier early-epoch guard, which lowered a legacy 100% fraction to the configured initial fraction for checkpoints without epoch_count, was removed because it stepped the fraction backwards at the same resolution. To restart a model from the initial fraction, use a clean run (--clean / --fresh).
  • Real-Time Cross-Model Checkpoint Parity: All training workflows (both standard PyTorch pipelines and governed YOLO runners) enforce continuous dual-path synchronization: active rung checkpoints (best.pt, best.pth, last.pt, progress.pth) are mirrored to checkpoints/<model_key>/ and LemGendaryModels/<model_key>/checkpoints/ on every epoch and stage completion.
  • Sub-Second Minibatch Cancellation Protocol: Training loops incorporate non-blocking cancellation listeners. For YOLO models, an on_train_batch_end callback sets trainer.stop = True within milliseconds of an abort signal, while standard PyTorch models evaluate cancel_check() at batch boundaries, permanently preventing mid-epoch runaway execution.
  • Mid-Rung Checkpoint Resumption & Stage Skip Protocol (v16.9.12): Solved premature epoch-1 restart bugs across both governed YOLO curricula and standard PyTorch pipelines. The checkpoint recovery subsystem (training/checkpoint/recovery.py and training/governance/yolo_governor.py) dynamically interrogates candidate checkpoint metadata (torch.load). If a ladder rung was already completed, it skips directly to the next stage; if interrupted mid-rung, it activates resume=True pointing to last.pt and resumes execution from ckpt_epoch + 2 without resetting optimizer states or epoch counters.
  • PyTorch 2.6+ Checkpoint Unpickling Resilience & Fallback (v16.9.34): PyTorch 2.6+ enforces weights_only=True by default during torch.load(). When loading complex serialized model topologies (such as Ultralytics DetectionModel checkpoints), standard loads raise an UnpicklingError. The recovery layer implements an automatic weights_only=False fallback handler, ensuring legacy and complex weights are loaded cleanly without dropping checkpoint metadata.
  • Cumulative Historical Telemetry Epoch Anchoring (v16.9.34): Resumption routines cross-reference physical checkpoint dictionary states against cumulative history stored in metrics.csv: completed_prior_epochs = max(completed_prior_epochs, csv_epochs). This permanently prevents multi-stage curriculum engines from resetting to early epoch counts when intermediate checkpoints lack embedded cumulative metadata.
  • Dynamic Horizon Runway Extension (v16.9.35): Solves static epoch denominator inversions (such as 266/150) where training runs extended past preset targets format against obsolete bounds. Calculates dynamic training horizons via stage_total_epochs = max(total_epochs, stage_start_epoch + 100) and continuously extends trainer.epochs ahead of execution by 100 epochs throughout long-running runs.
  • Telemetry 1-Indexed Epoch Synchronization (v16.9.35): Standardizes epoch serialization across TelemetryEngine.write_epoch_row so that 1-indexed global epoch counters map 1-to-1 with rows in metrics.csv, eliminating off-by-one overwrites between consecutive epoch executions.
  • Universal Highest-Epoch Checkpoint Selection (v16.9.41): Resolved a critical checkpoint rollback vulnerability across all 23 production models. Previously, checkpoint discovery prioritized progress.pth over latest.pth and best.pth. In long-running models with pre-existing intra-epoch snapshots (e.g. mirnet_exposure, nima_aesthetic_pro, nima_authenticity), an older progress.pth from early epochs could supersede latest.pth, threatening up to dozens of epochs of completed training. The recovery engine dynamically inspects candidate metadata (torch.load) across ("latest", "best", "progress", "latest_epoch") and selects the candidate checkpoint with the highest completed epoch and latest modification timestamp.
  • Automated Stale Progress Checkpoint Purge (v16.9.41): Injected automated lifecycle cleanup into CheckpointLifecycleManager: whenever latest.pth represents an epoch greater than or equal to progress.pth, the stale intra-epoch snapshot is immediately purged from checkpoints/, eliminating checkpoint ambiguity and preventing regression to earlier epochs.
  • Checkpoint Resumption Fraction Preservation & Post-Audit State Persistence (v16.9.43): Restores epoch_count, last_res_jump_epoch, last_action_epoch, and history inside SmartTrainingGovernor.load_state() prior to evaluating legacy state guards, and reconciles curriculum fraction and resolution against metrics.csv on startup so models at $100\%$ data fraction (sample_fraction = 1.0) never regress to $15\%$ on resume. Reorders run_training so metrics.csv records the active pre_audit_gov_state used during the completed epoch while latest.pth and best.pth persist the post-audit governor_state, and slices MultiTaskDataset and InstructionDataset manifolds deterministically in-memory (random.Random(42)) without re-initializing container readers.
  • Authoritative Single Source of Truth Persistence (LemGendaryModels/) (v16.9.12): Fixed workspace relative path resolution in recovery.py and aligned all training engines so that LemGendaryModels/<model_key>/checkpoints/ and LemGendaryModels/<model_key>/metrics.csv serve as the primary authoritative persistence storage across the entire development tree.
  • Literature & Reference Paper Citations (v16.9.12): Embedded canonical academic paper citations, conference publications, arXiv references, and BibTeX entries across all model documentation in LemGendaryModels/<model_key>/README.md via training/doc_generator.py.
  • Senior Developer Suite Audit & Pyrefly Diagnostic Remediation (v16.9.44): Systematically resolved Pyrefly static typing diagnostics across data/mt5_pipeline.py (Timestamp .hour traversal and epoch time conversion), models/core_restoration.py (direct up(x) invocation eliminating manual ConvTranspose2d parameter unpacking while preserving 16-byte memory alignment on Turing GPUs), models/forex_predictor.py (strict structural type guards on fused_project elements eliminating Module | Tensor type pollution), models/master_generative.py (explicit null-checks for from_pretrained subcomponents), training/export/ (strict nn.Module typing on export wrappers), and training/__init__.py (default MPLCONFIGDIR and MPLBACKEND initialization eliminating sandboxed font scan overhead). Full 100% test battery pass with zero warnings and zero suppressions.

2.5. Mixture-of-Experts (MoE) 11-Manifold Architecture

  • Double-Softmax Squeeze Protection: The TaskClassifier routing network natively isolates softmax activation from the loss engine, returning raw logits to prevent log_softmax gradient flattening when calculating Cross-Entropy gating loss.
  • Dynamic Perceptual LPIPS Balancing: Automatically intercepts batch task indices during joint training to apply dynamic, sample-specific LPIPS multipliers scaling from 0.005 (Face Parsing) to 0.050 (Vintage & Face Restoration). This permanently prevents aggressive structural tasks from mathematically overpowering subtle intensity-based manifolds (like Lowlight/Exposure) via head competition.
  • Dynamic Regex Ingestion & Unified Class Index Normalization (v16.9.137): Seamlessly routes tasks like Denoise, Deblur, Derain, Dehaze, SuperRes, and Vintage automatically through regex extraction of physical dataset filenames on the fly (professionalmultitaskrestoration_[task]_compiled...). 2.19. Forex Parquet Locality & Telemetry Progress Sync (v16.9.26)

  • Parquet Row-Group Locality Bottleneck & RowGroupAwareSampler: Parquet is a columnar format organized into discrete row groups (typically ~5,000 rows each). Accessing row $N$ within a compressed row group requires decompressing the entire group. Under standard PyTorch shuffle=True, row indices are selected uniformly at random across all 700+ row groups across multiple years. This causes an catastrophic ~98% cache miss rate against in-memory LRU buffers, inflating batch iteration times to ~55 seconds per batch. The engine resolves this by integrating RowGroupAwareSampler directly in training/core_loop.py for all Forex datasets:

    1. Buckets sample indices by parent row group locality keys ('parquet', year, row_group_id).
    2. Shuffles at the row group level across epochs via sampler.set_epoch(epoch).
    3. Yields indices within each row group contiguously, driving LRU cache hit rates from 2% to 99% and accelerating batch throughput to sub-second speeds (<0.5s/batch).

2.25. Monotonic Ratchet (Pair Rule) & RatchetViolation Guard (v16.9.67)

The governor moves through curriculum rungs $(r, f)$, where $r$ is the spatial resolution and $f$ the data fraction. The owner ruling for the ROBOTS.md Monotonic Ratchet Invariant is the pair rule. A transition from $(r_t, f_t)$ to $(r_{t+1}, f_{t+1})$ is allowed only if:

$$r_{t+1} \ge r_t \quad \land \quad \left(r_{t+1} = r_t \Rightarrow f_{t+1} \ge f_t\right)$$
  • Resolution never decreases: no code path lowers current_res during training.
  • Fraction never decreases within one resolution step: expansions use expand_fraction, $f_{t+1} = \max(f_t, \min(1, f_t + \Delta f))$ with $\Delta f = 0.20$. Values within 1% of full data snap to 1.0.
  • Fraction may reset when the resolution steps up: after a regular spatial jump the fraction restarts at the configured initial fraction (0.15), after a forced SOTA jump at 0.5.
  • Enforced guard: the torch-free module training/ratchet.py defines check_transition. Every governor transition (data propulsion, spatial jump, SOTA forced jump, loop-breaker breakout, VRAM veto) goes through SmartTrainingGovernor._commit_rung, which raises RatchetViolation (a ValueError) on a backward step instead of applying it.
  • Regression handling: on regression the governor holds the rung and cools the learning rate (Section 2.4). It never recoils fraction or resolution.
  • Resume: load_state restores the saved fraction as-is. get_state() and the 4-pillar check share the keys input_size and sample_fraction.
  • Tests: tests/unit/test_ratchet.py (15 torch-free tests) checks that a simulated run obeys the pair rule, that backward steps are rejected, that governor transitions go through _commit_rung, and that completion fails below the top rung or with missing keys.

2.26. Bounded Epoch Budget & Honoured Early Stop (v16.9.65)

After every epoch the engine (training/training/engine.py) asks EpochBudgetPolicy (training/epoch_budget.py) whether to continue, extend or stop. With the configured budget $E$, the extension step $e$ (training_budget.extension_epochs, default 10) and the extension ceiling $E_{\max}$ (training_budget.max_extension_epochs, default 0), the number of trained epochs is bounded:

$$E_{\text{trained}} \le E + E_{\max}$$

The policy decides in this order:

  1. converged: the 4-pillar completion invariant is met, so training stops.
  2. early_stop: the governor signalled early stop from audit_epoch, so training stops.
  3. The epoch is below the budget, so training continues.
  4. budget_reached: extensions are disabled (max_extension_epochs: 0, the shipped default), so training stops.
  5. extension_limit: the extension ceiling is used up, so training stops.
  6. budget_reached: the governor does not report improvement, so training stops.
  7. Otherwise the budget grows by $\min(e, E_{\max} - \text{used})$ epochs.

Every stop and every extension is printed and logged with its reason, and TrainingSummary.stop_reason records it. Resumed runs honour the configured budget, because the hidden 20-epoch floor on resume was removed. Pillar 4 needs 20 epochs, so a short diagnostic run always ends with budget_reached, never with converged. The per-model optimization.extension_epochs key is no longer read by the engine. The YOLO curriculum governor (Section 2.14) is unchanged. tests/unit/test_epoch_budget.py holds 15 torch-free tests.

2.27. Pareto Model Soup Service (v16.9.66)

blend_model_soup() in training/model_soup.py (torch-free) is the one service behind lemtrain soup and POST /api/models/{model_key}/soup (training/server/routes/soup.py).

  • Hub resolution: the models hub comes from config.yaml paths.checkpoints_root (default ../LemGendaryModels, the sibling repo; absolute values are refused). The service resolves <hub>/<model>/checkpoints/vault_*.pth and passes the list of files to create_pareto_model_soup.
  • Donors and weights: by default every vault_*.pth is blended, sorted by name. Optional donors (psnr, lpips, ...) select specific vaults (CLI --donors, API JSON body {donors, weights}; an empty body still works). Weights must match the donor count and be non-negative. Fewer than two donors are rejected.

The result is written to best_soup.pth next to the vaults unless another output is given.
$$\theta_{\text{soup}} = \sum_{k=1}^{K} \frac{w_k}{\sum_{j=1}^{K} w_j} \, \theta_k$$

  • Limits: BatchNorm statistics are not re-estimated after blending. Metadata, including governor_state, is copied from the first donor, and soup_weights stores the weights as given. The blend is not evaluated automatically, so any claim that it beats its donors must come from a measured evaluation.
  • SWA ingredient: since v16.9.107 a run with SWA enabled (Section 2.32) writes checkpoints/vault_swa.pth. The default glob picks it up, or name it with --donors psnr swa, so SWA plus soup blending (the ROBOTS.md Pareto Model Soup standard) works. SWA is off by default.

2.28. Publication-Grade FID & Unverified Historical FID Rows (v16.9.67)

validate_one_epoch (training/training/validation.py) computes FID with torchmetrics FrechetInceptionDistance(feature=2048), the 2048-dimensional final pooling layer of Inception-v3, for every model with fid in sota_targets. With real-image statistics $(\mu_r, \Sigma_r)$ and reconstruction statistics $(\mu_g, \Sigma_g)$:

$$\text{FID} = \lVert \mu_r - \mu_g \rVert_2^2 + \operatorname{Tr}\left(\Sigma_r + \Sigma_g - 2 \left(\Sigma_r \Sigma_g\right)^{1/2}\right)$$

Real and reconstructed uint8 images are fed in micro-chunks of at most two samples, so the transient Inception memory scales with the chunk, not with the validation batch:

$$\text{Mem}_{\text{peak}} = \mathcal{O}(b_{\text{chunk}} \cdot H \cdot W \cdot C), \quad b_{\text{chunk}} \le 2$$
  • Removed tool: before v16.9.67, tools/recalibrate_fid.py rewrote metrics.csv FID values with formulas (for example fid * 45 + lpips * 26, and a fixed 2.78 for epoch 2) and recomputed Quality_Score. That broke the Chart & Metrics Governance and Publication-Grade FID rules, and the tool was removed.
  • Unverified FID history: the rewritten rows of four models are not measured values: codeformer, ffanet_indoor, mprnet_deraining and mirnet_lowlight. Their historical FID values are unverified wherever they appear (model papers, metrics.csv, training charts). This paper cites no FID value for these models and publishes no replacement numbers.
  • Open item: the checkpoints must be re-evaluated with real Inception FID (feature=2048, chunks of at most two) or the rows excluded from charts. Since v16.9.107 the FID re-evaluation tool (Section 2.33) measures a checkpoint and records the rows as unverified; the measurements need a GPU and have not been run. The formula values are still in metrics.csv.

2.32. Stochastic Weight Averaging (v16.9.107)

training/training/swa.py adds optional SWA on torch.optim.swa_utils. It is configured in the swa section of config.yaml (validated by training/swa_config.py) and is off by default:

  • enabled (default false); start_epoch (first averaged epoch, overrides start_fraction) or start_fraction (default 0.75, the last quarter of the epoch budget).
  • swa_lr: when set, SWALR takes over the learning rate in the SWA phase and anneals over anneal_epochs (default 5) with anneal_strategy (cos or linear); the main scheduler is no longer stepped. null keeps the main schedule (averaging only).
  • update_every (default 1): average every N epochs of the phase.
  • eval_every (default 0): refresh BatchNorm, validate the averaged model and write vault_swa.pth every N updates; 0 does this once, when training ends. bn_update_batches caps the BatchNorm refresh (null uses the whole train loader).

With $n$ averaged epochs, epoch $t$ updates the running mean as

$$\theta_{\text{SWA}} \leftarrow \frac{n \, \theta_{\text{SWA}} + \theta_t}{n + 1}$$
  • Engine seam: one SwaPhase component. The engine calls it after the governor audit of each epoch and once after the loop. AveragedModel is created at the first SWA epoch. update_bn re-estimates BatchNorm statistics before the averaged model is validated.
  • Ratchet safety: SWA metrics go to the log and swa_metrics only, never to the SOTA tracker or the governor, so curriculum rungs still change only through _commit_rung (Monotonic Ratchet). A disabled run is unchanged.
  • Soup ingredient: the averaged weights after the BatchNorm refresh are saved as checkpoints/vault_swa.pth (Section 2.27). They are not promoted to best.pth.
  • Resume: the average, n_averaged and the SWALR state are kept in the checkpoints/swa_state.pth sidecar and restored when it matches the resumed epoch; otherwise averaging restarts with a warning. Cloud sync does not carry the sidecar yet.
  • Not implemented: Mini-SWA (the trigger_mini_swa flag is still unread) and Metric-Specific SWA (MS-SWA).
  • Tests: tests/unit/test_swa.py (18 CPU tests).

The applied multiplier is stored in the param group and survives a resume; head_lr_multiplier applies to groups tagged group: head (Section 2.38).
$$\eta_g \leftarrow \eta_g \cdot \frac{m_{\text{new}}}{m_{\text{applied}}}, \qquad \eta_g^{\text{base}} \leftarrow \eta_g^{\text{base}} \cdot \frac{m_{\text{new}}}{m_{\text{applied}}}$$

2.37. Shard I/O, Offset Cache & Locality Sampling (v16.9.148 to v16.9.154)

  • Byte-Offset Reads: training/data/containers/tar_offsets.py records (name, offset, size) of every member of an uncompressed shard. A member is read with one seek and one read instead of tarfile.extractfile(name), whose reverse linear name scan costs $\mathcal{O}(M)$ in a shard of $M$ members; the offset lookup is $\mathcal{O}(1)$. Compressed shards keep the tarfile path, and a short read (a shard changed after indexing) raises OSError and drops the handle.
  • Offset Cache: ShardOffsetCache keeps the tables in .shard_offsets.json next to the shards, or in a temp-dir fallback when the shard folder is read-only (Kaggle /kaggle/input). An entry is reused only while the shard's size and mtime match and every member lies inside the file; otherwise the shard is rescanned. Since v16.9.215 the file is the shipped shard_offsets.json with its own acceptance rule (Section 2.46).
  • Bounded Handles: HandlePool (training/data/containers/handle_pool.py) keeps at most 16 shard handles per process (max_open_handles) and closes the least recently used one. Handles are never pickled, and a forked worker closes inherited handles.
  • Measured Read Cost: on four 5,000-member shards (CPU, warm page cache) a sample took 188.6 us with tarfile reads and 29.7 us with offset reads; the index took 314 ms by header scan and 132 ms from the cache (training suite changelog v16.9.148).
  • Label 0: a falsy JSON sidecar label (class 0, score 0.0) no longer falls through to the next key.
  • Zero-Rebuild Curriculum Transitions: a fraction or resolution change re-slices the cached sample list, and the offset index travels with the pickled reader, so update_strategy, item reads and respawned loader workers never call scan_tar_members or tarfile.open. tests/unit/test_curriculum_rebuild.py pins this and checks that each larger fraction keeps every sample of the smaller one.
  • Locality Sampler: training/data/locality.py reads the data.locality section of config.yaml; since v16.9.159 it is on by default (window_shards: 4, fraction_block_size: 256; 0 turns either off). With window_shards set, the train sampler shuffles the shards per epoch and the samples inside windows of that many shards; the order is drawn from seed + epoch, splits across DDP ranks and resumes mid-epoch. On 50 shards of 1,000 samples with a window of 4, a 16-sample batch touches 3.9 shards instead of 13.8. With fraction_block_size set, a curriculum fraction is built from shuffled contiguous blocks inside each shard in a fixed block order, so the subsets stay nested across fraction steps (Monotonic Ratchet).

2.38. Quality Score, Optimizer Groups & Batch Invariant (v16.9.144 to v16.9.152)

$$\text{Quality Score} = \text{PSNR} + (\text{SSIM} \times 20) - (\text{LPIPS} \times 20)$$
  • FID as a Separate Gate: FID was measured every fifth epoch and added $(100 - \text{FID})$ only then, so the score jumped by 60 to 90 points on FID epochs and best.pth followed that cadence.   • Old Checkpoint Migration: restore_optimizer_state migrates the old two-group layout: each parameter keeps its Adam moments and step, each new group takes the hyperparameters of the group it came from, and the scheduler's per-group lists are widened, so the LR curve continues. A state that does not match keeps the fresh optimizer and logs a warning.
  • Exact-Divisor Batch Rule: the effective batch $B_{\text{eff}} = b_{\text{micro}} \times k$ ($k$ accumulation steps) stays exactly equal whenever the micro-batch shrinks to a budget $b_{\text{safe}}$: the new micro-batch is the largest divisor of $B_{\text{eff}}$ within the budget (fit_batch_to_budget). The rule applies after a resolution jump, on the resume VRAM clamp and in the OOM throttle (Section 2.39). The first setup still rounds $B_{\text{target}} / b$ (Section 2.35).
$$b_{\text{micro}}' = \max\{\, d \le b_{\text{safe}} : d \mid B_{\text{eff}} \,\}, \qquad k' = \frac{B_{\text{eff}}}{b_{\text{micro}}'}, \qquad b_{\text{micro}}' \times k' = B_{\text{eff}}$$
  • VRAM Refit on Resolution Jumps: after a jump the engine re-runs the VRAM audit at the new resolution (training/training/batch_budget.py) and fits the micro-batch to it; BatchNorm buffers and the train/eval mode are restored after the probe. The refit only shrinks the batch and runs only on CUDA. With an effective batch that has few divisors, the micro-batch can drop to 1.
  • Spatial Ladder Memory Analysis: activation memory scales with the pixels held at once, so chunked evaluation bounds the peak by the chunk and not by the dataset size $N$. Along the restoration ladder 256px -> 384px -> 512px -> 640px, $H \cdot W$ grows by 2.25, 1.78 and 1.56 per step, 6.25 in total, so the micro-batch that fits at 256 px needs about $1/6.25$ of the memory budget per sample at 640 px. Under the exact-divisor rule an effective batch of 24 with a budget of 5 trains at 4 x 6 and with a budget of 2 at 2 x 12.
$$\text{Mem}_{\text{total}} = \mathcal{O}(N \cdot H \cdot W \cdot C) \quad \text{vs} \quad \text{Mem}_{\text{peak}} = \mathcal{O}(b_{\text{chunk}} \cdot H \cdot W \cdot C)$$
  • Rung Entry Fraction: rung_entry_fraction decides the data fraction a new rung starts at (optimization.initial_fraction, then governor.manifold.initial_fraction, then 0.15). A SOTA-forced jump used to enter at a hardcoded 50%; both jump kinds now use it, through _commit_rung and its pair rule (Section 2.25).

2.46. Shard Offset Index & Fast WebDataset Open (v16.9.215 to v16.9.218)

  • Consensus Broadcasting: The coordinator tracks epoch syncs, learning rate recoils, and node parameters. Once a quorum is met, the hub broadcasts a unified federated average-sync gradient vector to all active edge nodes.

6.2. Memory-Sentinel WebGPU Zero-Copy Export

  • Opset 17 Hardening: The exporter is rigidly configured to ONNX opset_version=17 and dynamic axes are intentionally stripped (locked to a 512x512 spatial tile). This permanently prevents standard WebGPU "Slice" operator crashes during browser inference.
  • Crowdsourced Browser Nodes: SOTA manifolds exported via this pipeline enable crowdsourced, zero-copy training and inference directly within any user's mobile or desktop NPU-enabled web browser.

7.1. GenericCausalLLM Architecture & Dynamic HuggingFace Backbone Wrapping

  • Lightweight Mock Verification Pathway: Implements a native mock pathway (self.embed + self.lm_head) activated automatically during headless smoke tests or environments without CUDA hardware, ensuring 100% deterministic unit test execution across CI/CD pipelines.

7.4. Multi-Turn ChatML Loss Formulation & Assistant-Only Prompt Masking

During instruction tuning, computing loss across system prompts and user inputs severely impairs model generalization by penalizing the model for memorizing input tokens. The training engine enforces strict assistant-only supervised loss masking:

  1. ChatML Serialization: Formats multi-turn conversations into standard ChatML sequences:

    <|im_start|>system
{system_prompt}<|im_end|>
<|im_start|>user
{user_message}<|im_end|>
<|im_start|>assistant
{assistant_response}<|im_end|>

  2. Label Masking with -100 Ignored Index: Token targets corresponding to <|im_start|>system...<|im_end|> and <|im_start|>user...<|im_end|> are assigned label -100. Only token targets within <|im_start|>assistant...<|im_end|> retain their token IDs:

    $$L_i = \begin{cases} -100 & \text{if token } i \in \text{Prompt (System/User)} \\ y_i & \text{if token } i \in \text{Assistant Response} \end{cases}$$

  3. CrossEntropy Loss & Perplexity Tracking: PyTorch's nn.CrossEntropyLoss(ignore_index=-100) ignores masked prompt tokens during gradient backward passes. Real-time validation loss ($\mathcal{L}_{\text{CE}}$) is converted to validation Perplexity:

    $$\text{PPL} = \exp(\mathcal{L}_{\text{CE}})$$

7.5. Tri-Format Deployment Export: PyTorch, ONNX FP32/FP16 & Edge Quantization

Upon achieving validation convergence, the export subsystem (training/export/) compiles universal deployment artifacts across three formats:

  • QLoRA Adapter Weights: Standalone PEFT adapter checkpoint (adapter_model.safetensors and adapter_config.json) enabling zero-copy weight hot-swapping on shared inference servers.
  • Merged FP16 Safetensors: Full-rank merged weights (model.safetensors) synthesized by fusing LoRA matrices into base weights ($W_0 + \Delta W$), optimized for native vLLM and HuggingFace pipelines.
  • GGUF / ONNX / WebGPU Quantization: Exported ONNX compute graphs (model_fp32.onnx, model_fp16.onnx) and quantized GGUF binaries (q4_k_m.gguf) for real-time edge inference on consumer CPUs, NPUs, and desktop runtimes.

7.6. Edge Hardware Optimization Profile (4GB VRAM Containment)

To execute fine-tuning of 1.5B+ parameter causal language models on consumer workstations constrained to 4 GB VRAM (e.g. NVIDIA GeForce GTX 1650), the training suite deploys a multi-tier memory containment profile:

  • NF4 Quantization: Encodes frozen base model parameters into 4-bit NormalFloat tensors, slashing baseline memory footprints to ~900 MB.
  • Activation Gradient Checkpointing: Recomputes intermediate layer states on the backward pass via gradient_checkpointing_enable(use_reentrant=False), preventing activation VRAM blowouts.
  • SDPA Execution: Adopts native C++ Scaled Dot-Product Attention (attn_implementation="sdpa"), eliminating memory overhead from quadratic dense attention matrices.
  • Paged 8-bit AdamW Optimization: Integrates bitsandbytes.optim.PagedAdamW8bit, automatically paging optimizer momentum and variance states across CUDA unified memory when VRAM boundaries approach saturation.
  • Curriculum Context Clamping: Constrains sequence lengths to 512 tokens with micro-batch size 1 and 16 accumulation steps for edge training.
