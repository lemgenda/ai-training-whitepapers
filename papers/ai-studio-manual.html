1. Abstract

The LemGendary AI Studio GUI is a hardware-aware command center engineered to make deep learning dataset synthesis, neural network training, and cloud deployment accessible to everyone from senior machine learning researchers to high school students and non-technical hobbyists. When something goes wrong, the Report Issue button packages a description, annotated screenshots and recent telemetry for the maintainers (chapter 13).

The Gardening Model Rule

To ensure absolute operational clarity, every control, workflow, and safeguard in this manual is designed according to the Gardening Model Rule:

If a 75-year-old grandmother wants to train an AI model using photos of her garden roses, tomato plants, and soil to automatically detect plant diseases and enhance low-light garden photographs, she should be able to complete the entire pipeline from environment setup to Kaggle cloud publishing purely by clicking intuitive buttons in the GUI, with zero command-line commands, zero code editing, and zero risk of freezing her computer.

The system achieves this through three foundational engineering principles:

  1. Deterministic One-Click Automation: All complex toolchains, Python virtual environments, CUDA drivers, wheel resolutions, and dependencies are provisioned automatically through the 7-Stage Clean Install Pipeline.
  2. Nuclear Memory Protection (The Sawtooth Governor): When training complex vision models, the GUI continuously probes hardware VRAM. If memory approaches capacity, the system automatically downscales batch sizes and applies dynamic gradient accumulation, guaranteeing that your machine never suffers an Out-of-Memory (OOM) crash or system freeze.
  3. Comprehensive Contextual Guidance: Every single interactive button, switch, input field, and status indicator is accompanied by a contextual hover icon (?) delivering instant, plain-English explanations of what the control does, what files are affected, and what safeguards are active.

2.3 Centralized State (Zustand) & Modular Micro-Components

To ensure instantaneous UI responsiveness, eliminate prop drilling, and prevent race conditions when streaming high-frequency training metrics, the application state is governed by a unified Single Source of Truth (SSOT) Zustand store (src/store/useStudioStore.ts):

  1. Ecosystem Mesh Health: Persists real-time connection status across the tripartite sidecars (Ports 8000, 8100, 8200) with automatic re-poll triggers and autonomous cold boot controls.
  2. Global Telemetry Ring Buffer: Keeps the latest 200 log events with ANSI color parsing, filtering and clipboard export; the Report Issue form attaches them as telemetry.
  3. Hardware Accelerators: Caches GPU VRAM profiles, temperature sensors, compute utilization matrices, and Sawtooth Governor headroom telemetry.
  4. Active Job Management: Tracks running training and compilation jobs; a stop request counts only when the sidecar confirms it (section 6.3).
  5. Open Modal: One store field (activeModal) records which dialog is open: config, tests or bug-report.
  6. Offline Catalogs: The model and manifold catalogs come only from the sidecars; there are no hand-written fallback lists (removed in v2.10.34). While the LemGendary Model Training Suite or the LemGendary Dataset Compiler Suite is offline or returns an empty list, the view shows an empty state with a message to start the sidecar (the training view also has Retry) and reloads the real list once the sidecar answers.
  7. Control ID Registry: Interactive controls carry stable DOM IDs, listed with their endpoints in GUI_CONTROL_REGISTRY.md (for example tab-dashboard, header-btn-report-issue, dash-btn-run-pipeline). Tests and the Report Issue module select rely on them.
  8. Shared Micro-Components & Utilities:
    • Modal.tsx: Shared dialog used by Report Issue, the annotator and the Clean Install confirmation: focus stays inside, Escape closes only the innermost dialog, and focus returns to the button that opened it.
    • ValidationBanner.tsx: Centralized banner component with auto-detected severity (info, success, warning, error), dismiss handlers, and full accessibility semantics.
    • HoverPinPopover.tsx: High-performance CSS hover and native semantic <button> pin popovers for SOTA targets and upstream sources.
    • src/utils/clipboard.ts: Dedicated zero-loss clipboard export utility supporting modern asynchronous navigator.clipboard.writeText with legacy fallback for sandboxed webviews.

3.2 Write-Only Secrets & Cloud Tokens

Secrets are write-only from the GUI. The Environment Manager never sends a stored value back: GET /api/secrets returns for each credential only whether it is set (has_value) and its last 4 characters (value_hint). Each credential therefore shows set (••••1234), set or not set, and there is no Show/Hide toggle.

  • Replace a value: Type the new value in the credential's password field (replace-secret-{secret_id}) and save.
  • Keep a value: Leave the password field blank; saving keeps the stored value.
  • Add a credential: Use "+ Add New Secret", fill in the service, label, username and secret, then save.
  • After saving: The masked list is reloaded, so the values you typed leave memory. Save errors show the server's message (for example a failed Kaggle check), and legacy credential files that were skipped or failed are listed.

Secrets & Tokens Vault Numbered Reference

  1. Configuration Editor Modal Title: Header confirming active credentials and token management workspace.
  2. Active Cloud Service Profile Badge: Visual badge identifying service provider (e.g. Kaggle, Google Drive, GitHub, MetaTrader 5).
  3. Requirement Level Badge: Clearly flags mandatory vs optional platform dependencies (MANDATORY for Kaggle API access, OPTIONAL for secondary mirrors).
  4. Toggle Add New Secret Form Button: Expands interactive credential registration form to add additional service accounts.
  5. Save Secrets to Ecosystem Button: Sends new and replaced values to the Environment Manager (POST /api/secrets), which stores them in .secrets.yaml and propagates the legacy single-token files (.kaggle_token, .kaggle_users, .mt5_credentials). Blank fields keep the stored values.
  6. New Secret Service Type Dropdown: Selects target cloud platform for new credential entry.
  7. Secret Label / Description Input: Human-readable label for credential identification (e.g. Personal Primary Account).
  8. Account Username / Identifier Input: Cloud service username or account identifier.
  9. Secret Token / API Key / Password Field (new-secret-input): A password field; the value is sent on save and never shown again.
  10. Add Secret Submit Button: Adds the credential to the list; it is stored only when you save.

4. One-Click Environment Setup: The 7-Stage Clean Install Pipeline

Before training an AI model, your computer must have the correct software libraries installed. Traditionally, this required typing dozens of cryptic terminal commands. The AI Studio eliminates this completely through the automated 7-Stage Clean Install Pipeline.

Clean Install Confirmation

A clean install deletes and rebuilds environments, so it always asks first. The dialog (pipeline-dialog-clean-install) lists what will be deleted across all workspace projects:

  • The .venv virtual environment of every managed Python project (recreated from the manifests).
  • The node_modules folder of every Node project (reinstalled with npm).
  • Every process running from those virtual environments, including running sidecars (stopped first).

Focus starts on Cancel (pipeline-btn-clean-cancel); Cancel or Escape closes the dialog without sending anything. Only Delete and reinstall (pipeline-btn-clean-confirm) starts the run with clean: true. The run can take a long time and cannot be undone.

Real-Time Telemetry Progress Tracker & Installation Safeguards

During Step 4 requirements and package synchronization, dependency installations can take several minutes to resolve and compile binary wheels. To provide continuous visual feedback and guarantee operators know the pipeline is actively working rather than stuck, an animated progress tracker (TelemetryProgressTracker) mounts directly above the monospace telemetry stream:

  • Amber Pipeline Theme: Highlights active pipeline operations with high-contrast amber styling (var(--accent-amber, #ffd166)) and a glowing gradient progress bar (linear-gradient(90deg, #f59e0b 0%, #ffd166 60%, #00f0ff 100%)).
  • Real-Time Requirement Counts: Live progress ratio metrics (e.g. [12/28 requirements]) show precisely how many dependencies have been processed.
  • Wheel Download Metrics & ETA: Displays active package names, download transfer speeds (e.g. 14.2 MB/s), byte ratios, and estimated time remaining.
  • Indeterminate In-Flight Indicators: When dependencies are resolving or building wheels, the progress bar displays an animated in-flight pulse, assuring operators of active execution.
  • Card-Level Progress Indicators: Each running step card in the 7-stage grid displays an animated progress bar along its bottom edge while executing.

11.1 Dynamic Configuration & Environment Overrides

Endpoint addresses and ports are completely decoupled from code literals. Production and remote environments can override service locations via standard environment variables:

  • VITE_ENV_MANAGER_URL: Base HTTP URL for the Environment Manager (default: http://127.0.0.1:8000).
  • VITE_DATASET_COMPILER_URL: Base HTTP URL for the Dataset Compiler Suite (default: http://127.0.0.1:8100).
  • VITE_TRAINING_SUITE_URL: Base HTTP URL for the Model Training Suite (default: http://127.0.0.1:8200).

The toWebSocketUrl() utility parses HTTP/HTTPS URLs and maps them automatically to corresponding ws:// or wss:// protocols, providing seamless transition from local loopback ports to secure TLS cloud deployments.

11.2 Semantic Origin Routing & Telemetry Stream Governance

Telemetry event streams are classified using semantic origin routing rather than brittle port number or regex guessing:

  • LemGendary Model Training Suite logs carry the origin training-suite and appear in the training telemetry console.
  • LemGendary Dataset Compiler Suite logs carry the origin dataset-compiler and appear in the compiler view's log panel.
  • Consecutive rapid carriage-return progress ticks (\r) roll up in-place via rollupTelemetryEvents(), keeping the active progress state visible at the terminal cursor while preserving discrete loss metrics, learning rates, checkpoint saves, and milestone events in terminal history.

11.3 Typed API Client Contracts (src/api/client.ts)

The desktop application talks to the sidecars through typed asynchronous TypeScript functions that all use sidecarFetch. For multi-objective optimization, the client calls the Pareto Model Soup engine on the LemGendary Model Training Suite:

export async function blendModelSoup(
  modelKey: string,
): Promise<ModelSoupResult> {
  const res = await sidecarFetch(
    `${TRAINING_BASE}/api/models/${modelKey}/soup`,
    { method: "POST" },
  );
  if (!res.ok) {
    throw new Error(`Failed to blend model soup: ${res.statusText}`);
  }
  return res.json();
}

This call interpolates the weights of specialized vault checkpoints (vault_psnr.pth, vault_lpips.pth, vault_plcc.pth, vault_srcc.pth, and others) on disk without retraining. ModelSoupResult stands for the returned object with model_key, success and soup_checkpoint.

13. Reporting an Issue

When something does not work, the Report Issue form collects what the maintainers need: your description, annotated screenshots and recent telemetry. The LemGendary Environment Manager saves everything as a ZIP file on your computer and opens your own mail client; no password or mail account is stored in the app.

13.1 Opening the Report Issue Form

Click Report Issue in the header (header-btn-report-issue). The form opens with Module set to the tab you were working in; change it if the problem belongs elsewhere.

  1. Your email (bug-modal-email): The address the maintainers can reply to.
  2. Module (bug-modal-module): One entry per sidebar tab.
  3. What happened? (bug-modal-description): At least 50 and at most 10,000 characters. The counter below the field shows how many you have typed. Describe what you did, what you expected and what happened instead.
  4. Attach telemetry (bug-modal-telemetry): On by default (section 13.3).
  5. Screenshots: Up to 5 annotated screenshots (section 13.2).
  6. Recording: One optional recording of the app window (section 13.6). Outside the desktop app the field is disabled with the note "Screen recording is available in the desktop app".

Note: The figure for this chapter (the Report Issue form, the annotator and the success view) will be added with the next screenshot refresh.

13.2 Screenshots & Annotation

Click Capture screenshot (bug-modal-btn-add-screenshot). The app takes a picture of its own window, leaving out the Report Issue form itself, and opens the annotator:

  • Drag over the picture (annotator-canvas) to draw one highlight rectangle around the problem. A new drag replaces the previous rectangle.
  • Save (annotator-btn-save) adds the picture to the form. It is stored as WebP, or PNG where WebP export is not available. A picture over 5 MB is halved in size, up to three times, until it fits.
  • Retake (annotator-btn-retake) captures the window again; Cancel (annotator-btn-cancel) or Escape discards the capture and returns to the form.

Each saved screenshot appears as a thumbnail with a Remove button. After 5 screenshots the capture button is disabled.

13.3 Telemetry

With Attach telemetry on, the form attaches the recent log events (up to the last 200) as a CSV file with the columns timestamp, status, source and message. Turn it off if the log contains information you do not want to share.

13.4 Sending & the Local ZIP Report

Click Send report (bug-modal-btn-submit). The form is checked first; problems are shown under the matching field. The Environment Manager then:

  1. Saves the report as bug_report_<timestamp>.zip in the bug-reports folder at the workspace root. The archive holds report.csv, the screenshots, the telemetry file and the recording, when attached.
  2. Opens your mail client with the recipient and subject filled in.
  3. Opens the bug-reports folder in your file manager.

The success view shows the archive name and its path relative to the workspace, the recipient and the subject. Attach the ZIP file to the mail and send it. If the mail client did not open, use Copy address (bug-modal-btn-copy-address) and Copy subject (bug-modal-btn-copy-subject) and write the mail yourself; a note also tells you when the folder did not open. Done closes the form and clears it.

Size limits: 5 screenshots of at most 5 MB each, telemetry at most 2 MB, and 80 MB for the whole report.

13.5 When Sending Fails

  • Environment Manager is not running: Start it from the Dashboard service tiles and send again; your input stays in the form.
  • A field is rejected: The server's message appears under the field (for example a description that is too short).
  • Report too large: Remove a screenshot and try again.
  • Other server errors: The message is shown at the top of the form.

13.6 Screen Recording

In the desktop app on Windows you can attach one short recording of the app window (only this window, at most 60 seconds of recorded time):

  1. Click Start recording (bug-modal-btn-start-recording). The Report Issue form hides and a control bar (recording-control-bar) shows the state and the elapsed time against the limit.
  2. Reproduce the problem. Pause (recording-btn-pause) and Continue (recording-btn-resume) stop and restart the clock; paused time does not count.
  3. Click Stop and attach (recording-btn-stop). The form returns with the clip summary (bug-modal-recording-summary: length, resolution, size, MP4). Remove recording (bug-modal-btn-remove-recording) discards it.

Recording stops by itself at the 60-second limit or when the capture fails; the error appears in the form. The clip is H.264 MP4 at 24 frames per second, scaled into 854x480, and is sent as recording.mp4 (the Environment Manager accepts up to 50 MB). On macOS and Linux the recorder reports that recording is not supported on this platform yet; describe the steps in the description instead.
