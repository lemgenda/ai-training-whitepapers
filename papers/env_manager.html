1. Abstract

The LemGendary Environment Manager (release v16.9.18-STABLE) is the infrastructure layer of the LemGendary ecosystem: it probes hardware, provisions and audits virtual environments, keeps dependency manifests aligned, validates the workspace and serves this functionality to the LemGendary AI Studio GUI as a local sidecar on port 8000. It addresses environmental drift, non-deterministic wheel resolution and accelerator fragmentation through a seven-step pipeline that couples device probing, one-way manifest synchronization with a downgrade guard, reverse-dependency upgrade classification with a constraint-preserving pip dry-run that fails closed, and real-time WebSocket telemetry. The pipeline is non-destructive by default; a clean reinstall needs an explicit option. The sidecar accepts browser requests only from AI Studio GUI origins, never returns stored secrets, runs package updates as background jobs and packages bug reports into a local ZIP archive for the operator's own mail client.

2. High-Velocity Optimizations

High-velocity execution across high-performance computing pipelines mandates deterministic sub-second environment inspection and rapid package reconciliation. The LemGendary Environment Manager achieves high throughput via an optimized dependency resolution graph and lazy evaluation of system probes.

Let $\mathcal{P} = \{p_1, p_2, \dots, p_N\}$ denote the set of managed projects, and $\mathcal{R}_i = \{r_{i,1}, r_{i,2}, \dots, r_{i,M}\}$ represent the requirement constraints for project $p_i$. The dependency verification complexity is bounded by:

$$T_{\text{verify}} = \mathcal{O}\left(\sum_{i=1}^{N} |\mathcal{R}_i| \cdot \log |\mathcal{I}_i|\right)$$

where $\mathcal{I}_i$ represents the set of installed site-packages within the virtual environment of project $p_i$. By querying pre-indexed JSON manifest metadata rather than re-invoking package inspection iteratively, package state lookup resolves in amortized $\mathcal{O}(1)$ time.

Liveness and auditing are separated. GET /api/ping answers in constant time without any I/O and is the probe the GUI uses to decide whether the sidecar is online; GET /api/health remains the full audit (prerequisites, hardware and pip list per project) for the Health panel.

Disk space recovery and cached package deduplication follow a deterministic reclamation model:

$$S_{\text{recovered}} = \sum_{c \in \mathcal{C}_{\text{stale}}} \text{Size}(c) + \sum_{w \in \mathcal{W}_{\text{orphan}}} \text{Size}(w)$$

where $\mathcal{C}_{\text{stale}}$ represents expired pip cache wheels and $\mathcal{W}_{\text{orphan}}$ represents unreferenced bytecode caches across isolated project virtual directories.

3. Hybrid Cloud & Registry Integration

Seamless execution between local development stations (Windows 11 with DirectX/DirectML, CUDA, or ROCm) and cloud execution clusters (Kaggle Linux environments, headless HPC nodes) demands resilient registry binding.

The system implements dynamic index routing based on probed hardware attributes. On CUDA hosts the index depends on the NVIDIA driver major version $d$ (select_cuda_torch_index()); an unknown or unparseable driver version selects cu126:

$$\text{IndexURL}(H) = \begin{cases} \text{.../whl/cu126}, & \text{if } H.\text{backend} = \text{CUDA} \land d \ge 560 \\ \text{.../whl/cu121}, & \text{if } H.\text{backend} = \text{CUDA} \land 535 \le d < 560 \\ \text{.../whl/cu118}, & \text{if } H.\text{backend} = \text{CUDA} \land d < 535 \\ \text{.../whl/rocm6.0}, & \text{if } H.\text{backend} = \text{ROCm} \\ \text{.../whl/cpu}, & \text{otherwise (DirectML or CPU)} \end{cases}$$

where .../whl/ stands for https://download.pytorch.org/whl/.

3.1 Sibling Surgery & Architectural Decoupling

Prior architecture relied on redundant, monolithic PowerShell scripts (lemgendary_env_manager.ps1) duplicated across sibling project trees (lemgendary-training-suite and lemgendary-datasets). This structural fragmentation resulted in divergent dependency specifications, uncoordinated pip cache mutations, and failure modes when deploying to headless POSIX runtimes.

The Sibling Surgery protocol extracts environment management into an autonomous, decoupled microservice. Sibling entrypoints (lemgendary_models_hub.ps1 and lemgendary_datasets_hub.ps1) delegate bootstrap and reconciliation workflows via a standardized Inter-Process Communication (IPC) delegation pattern:

$$\mathcal{D}(P, c) = \text{SubprocessExecute}\left(\text{lem-env}, c, \text{Target} = P\right)$$

If the centralized lem-env binary is absent, the launcher executes a self-healing bootstrap sequence that clones and installs lemgendary-env-manager in editable mode before delegating execution.

3.2 PEP 508 Cross-Platform Invariants

To eliminate wheel collision across heterogeneous runtime operating systems, requirements manifests enforce strict PEP 508 platform markers:

$$\mathcal{M}(w, P) = \begin{cases} \text{Install}(w), & \text{if } \text{Eval}(\text{Marker}(w), P) = \text{True} \\ \text{Omit}(w), & \text{otherwise} \end{cases}$$

This formalization guarantees that Windows-specific binary extensions (e.g. MetaTrader5 dynamic link libraries and DirectML backends) are conditionally excluded in Linux cloud instances (sys_platform == 'win32'), eliminating silent import failures in Kaggle and Colab container runs.

4. Multi-Modal & Format Resilience

The framework guarantees format resilience across Python packages and Node.js tooling. The central files in lemgendary-env-manager/requirements/ are the single source of truth; each sibling manifest is a generated copy. Sync is one-way, from central to sibling (lem-env sync, POST /api/manifests/sync and pipeline steps 4 and 6):

  • requirements-training.txt → lemgendary-training-suite/requirements.txt
  • requirements-datasets.txt → lemgendary-datasets/requirements.txt
  • requirements-env-manager.txt → lemgendary-env-manager/requirements.txt
  • requirements-documentation.txt → lemgendary-docs/requirements.txt
  • lemgendary-ai-studio-gui.package.json → lemgendary-ai-studio-gui/package.json
  • lemgendary-env-manager.package.json → lemgendary-env-manager/package.json

Sync never takes anything away from a sibling. Let $C$ and $S$ be the central and sibling requirement sets, compared per package and environment marker, and $\text{floor}(r)$ the lowest version a requirement admits. The copy is written only when the drift set is empty:

$$\text{Drift}(C, S) = \{ s \in S : s \notin C \} \cup \{ s \in S : \text{pinned}(s) \land \lnot \text{pinned}(C_s) \} \cup \{ s \in S : \text{floor}(C_s) < \text{floor}(s) \}$$

A non-empty drift set leaves both files unchanged and is reported as a DRIFT: warning (find_requirement_drift, find_package_json_drift); the fix is to raise the central pin and sync again.

The environment manager enforces strict schema parsing resilience:

$$\text{Valid}(\text{line}) = (\text{line} \in \mathcal{M}_{\text{index}}) \lor \text{Match}(\text{line}, \text{PEP508\_REGEX})$$

pip output is parsed fail-closed. pip stdout and stderr are captured on separate pipes, so warnings never corrupt --format=json or --report - output. A failed or unparseable pip list or pip inspect raises PipJsonError, and the upgrade classifier then blocks every candidate instead of guessing.

6. Synthesis Flow & Topology

The Smart Install Pipeline operates as a directed acyclic synthesis flow comprising seven deterministic stages:

$$\mathcal{G} = (\mathcal{V}, \mathcal{E}), \quad \mathcal{V} = \{v_1, v_2, \dots, v_7\}$$
  1. Hardware Discovery ($v_1$): Evaluates OS architecture, CPU topology, system RAM, GPU accelerators, and MetaTrader 5 installation. Resolves the PyTorch index URL (Section 3). MT5 detection uses a registry-first strategy with terminal64.exe file-version extraction for authoritative version reporting even when winget has no record of the installation.
  2. Toolchain Audit ($v_2$): Verifies the host Python runtime, Git binaries, Node.js / npm, PowerShell modules, and MetaTrader 5 package managers. Resolves local linters from lemgendary-env-manager/node_modules/.bin. pyproject.toml declares requires-python >=3.10 and the bootstrap accepts 3.10, but the validator (Path.walk) and the venv manager (shutil.rmtree(onexc=...)) use Python 3.12 APIs, so Python 3.12 is the effective minimum.
  3. Virtual Environments Provisioning ($v_3$): Identifies missing or invalid virtual environments across Python projects and creates isolated .venv trees. A default run keeps valid venvs and node_modules and stops no processes. Only a clean run (lem-env install --clean or "clean": true on POST /api/pipeline/run) deletes every .venv and node_modules, stops processes running from those venvs and reinstalls; the environment executing the pipeline is preserved. A failed node_modules purge is reported as a step error.
  4. Requirements Synchronization & Installation ($v_4$): Writes the central manifests to the siblings under the downgrade guard (Section 4) and installs wheel distributions under PEP 508 filters. Runs npm install for lemgendary-ai-studio-gui and lemgendary-env-manager. Applies OpenCV variant normalization after install to guarantee a single cv2 provider per project.
  5. Dependency Audit & Safe Upgrades ($v_5$): Routes by discovery metadata: every Python project gets the pip path and every project with a package.json (has_npm_manifest) gets the npm path (npm outdated), so a dual-stack project gets both. Every pip candidate is classified as safe or blocked by a reverse-dependency check (via pip inspect --local) followed by a constraint-preserving pip dry-run. Only safe candidates are upgraded; blocked candidates carry a reason describing the violated requirement. Torch-family packages on CUDA hosts are resolved against the PyTorch CUDA index and filtered to the installed subset.
  6. Codebase Verification ($v_6$): Executes py_compile bytecode compilation, ESLint, TypeScript check, RFC 8259 JSON validation, PowerShell analysis (PSScriptAnalyzer), markdownlint, yamllint, W3C HTML validation, WCAG 2.2 AA accessibility audit, and ecosystem domain verifications (dataset schemas and training checkpoint integrity). The documentation check compares each Markdown and HTML pair by H2 count, table count and length ratio; it is not a word-for-word comparison.
  7. Health Matrix Generation ($v_7$): Compiles global telemetry into an aggregated health status matrix for desktop and CLI display, including manifest coverage, single-manifest package inventory, and npm workspace drift.

6.1 Entrypoints & Operator Interfaces

The LemGendary Environment Manager provides a unified command line interface (lem-env) and a background API server for multi-repository Python and Node.js environments. Its commands are probe, audit, install, update, sync, validate, clean, serve, setup-hooks and hooks. All operations can be invoked directly from the terminal, through the interactive PowerShell menu, or via sibling launcher scripts. lem-env update --project X plans and applies upgrades for project X only; an unknown project exits with code 1.

Detailed command recipes, operational procedures, and complete CLI syntax are documented in the Master CLI Operations Manual. Complete API route specifications and WebSocket schemas are available in the Master REST & WebSocket API Specification.

# Install Environment Manager in editable mode
pip install -e ./lemgendary-env-manager

# Verify installation
lem-env --help

The PowerShell menu (.\lemgendary_env_manager.ps1) provides an interactive loop that returns to the menu after each command. It also manages the API server as a background PowerShell job, allowing it to remain running while the menu stays accessible.

6.2 Dual-Interface Telemetry Topology

The control topology couples a headless CLI engine (lem-env) and a reactive desktop GUI shell (lemgendary-ai-studio-gui) via an asynchronous non-blocking event stream:

$$T_{\text{telemetry}} = \mathcal{O}(1) \quad \text{amortized broadcast}$$

Pipeline and update worker threads dispatch typed PipelineEvent messages to connected WebSocket clients through asyncio.run_coroutine_threadsafe(), which bridges the worker threads to the server event loop without blocking the UI during prolonged package compilation and bytecode verification. The FastAPI @asynccontextmanager lifespan handler starts the ecosystem sidecars in the thread pool on startup.

To eliminate unobservable blocking stalls during dependency installation, the execution subsystem deploys unbuffered real-time streaming generators (stream_pip_with_recovery, stream_npm_install, stream_install_requirements) that yield subprocess output line-by-line using PYTHONUNBUFFERED="1" and --progress-bar on. Streaming lines are parsed in real time to extract wheel download metrics (transfer bandwidth, byte ratios, and ETA countdowns), requirement progress ratios ([k/N requirements]), and discrete stage milestones, broadcasting typed progress events (is_progress=True) over the /ws/log WebSocket channel without terminal stream saturation.

6.3 Desktop GUI State Aggregation & Multi-Sidecar Ecosystem Observability

To minimize HTTP handshake overhead in desktop graphical clients, the Environment Manager daemon exposes high-density aggregated endpoints:

  • Liveness (/api/ping): Constant-time GET and HEAD probe returning status, service and version.
  • State Aggregation (/api/gui/state): Packages system identity, hardware sensors, discovered repository trees, and active pipeline statuses into a single non-blocking payload, eliminating waterfall polling.
  • Ecosystem Sidecar Interoperability (/api/gui/ecosystem): Probes the lemgendary-datasets sidecar (port 8100) and the lemgendary-training-suite sidecar (port 8200) one after the other in the thread pool, each with a 1.5 s timeout, and reports their health next to the env manager itself (port 8000) for the lemgendary-ai-studio-gui status bar.
  • Service Control (/api/services/{service_id}/start and /stop): Starts and stops the sidecar daemons.
  • Governance & Maintenance Endpoints (/api/hooks/install, /api/clean): Provides programmatic endpoints for ecosystem-wide Git hook installation and recursive temporary cache/staging artifact purges with space recovery telemetry.
  • API Contract: openapi.json is regenerated from the running app and includes run-step, hooks/install, ping, update/status, shutdown and bug-report, so Tauri Rust and TypeScript clients can be generated from it.

6.4 Background Update Jobs

POST /api/update no longer runs the upgrade inside the request handler. A dry run returns the plan. A real run starts a background job (env_manager/update_jobs.py, UpdateJobManager) and returns at once with status: "accepted" and a job_id; progress is streamed over /ws/log and GET /api/update/status returns the current or last job. The project field limits the plan to one project, and an unknown project returns 404.

Updates are mutually exclusive with each other and with the pipeline. With $U$ the running update job and $\Pi$ the running pipeline:

$$\text{Admit}(\text{req}) = \lnot U \land \lnot \Pi, \qquad \text{otherwise HTTP } 409$$

A runner failure is logged and recorded as status: "failed" with an error, and the lock is released.

6.5 Security Model

The sidecar binds to 127.0.0.1 by default and shares one security contract with the other two sidecars and the GUI:

  • Origin Guard (env_manager/security.py): a request whose Origin header is not an AI Studio GUI origin (tauri://localhost, http://tauri.localhost, https://tauri.localhost, http://localhost:1420, http://127.0.0.1:1420) gets 403, and WebSocket handshakes from a foreign origin are refused.
  • Client Header: browser requests that use POST, PUT, PATCH or DELETE must send X-LemGendary-Client: ai-studio-gui. The custom header forces a CORS preflight, which blocks cross-site form posts. Requests without an Origin (CLI, scripts, tests) are not affected.
  • Closed CORS: the CORS policy lists the same origins, explicit methods and headers, and allow_credentials=False instead of allow_origins=["*"].
  • Masked Secrets (env_manager/secrets_vault.py): GET /api/secrets returns only has_value and a value_hint (last 4 characters, empty for values shorter than 8) and has no side effects. POST /api/secrets is write-only: an empty value keeps the stored one, a non-empty value replaces it. The vault file .secrets.yaml is written atomically with a backup. Kaggle credentials are propagated only to repositories that read them, without invented usernames, and the result is reported in propagation (written, skipped, failed). All secret files are ignored by git.

6.6 Bug Report Endpoint

POST /api/bug-report receives the report built by the AI Studio GUI. The server sends no email and stores no SMTP credentials:

  • Validation: a Pydantic model checks the multipart fields (email, module, a description of 50 to 10,000 characters, app_version, current_tab). Uploads are checked by count, size, declared type and leading bytes: up to 5 screenshots (PNG or WebP, 5 MB each), an optional telemetry CSV (2 MB) and an optional recording (WebM or MP4, 50 MB), at most 80 MB in total. Errors return 422 or 413 with the field in loc.
  • Archive: bug_report_<UTC timestamp>_<id>.zip holds report.csv (written with the csv module; cells that look like formulas are prefixed with '), the telemetry file and the uploads. It is saved to bug-reports/ at the workspace root, outside every repository.
  • Hand-off: a PlatformAdapter protocol opens the mail client (mailto: with recipient and subject) and reveals the archive in the file manager. The response returns the archive's path relative to the workspace root and whether each step worked; the request succeeds even when the mail client cannot be opened, because the archive is saved.
  • Configuration: recipient, subject, reports folder and limits are defined in one place, env_manager/bug_report/config.py (BugReportSettings).

7. Unified Models Registry

The environment framework interfaces directly with the LemGendary Unified Models Registry and Dataset Compilers. By maintaining environment alignment across all sibling repositories, models trained within lemgendary-training-suite can be exported directly into target deployment runtimes without runtime DLL mismatches or missing operator kernels.

$$\forall p \in \mathcal{P}, \quad \text{Compat}(\text{PythonVersion}(p), \text{ONNXRuntime}(p)) = \text{True}$$

This structural invariant ensures that inference runtimes, MetaTrader bridges, and dataset compilers operate in total environmental equilibrium.

8. Conclusion

The LemGendary Environment Manager reduces environmental divergence across the machine learning development lifecycle. A standalone Python engine with a CLI and a local sidecar provides driver-aware PyTorch index selection, one-way manifest synchronization that refuses downgrades, fail-closed upgrade classification, a non-destructive install pipeline, background update jobs and real-time telemetry. The sidecar accepts browser requests only from the AI Studio GUI, keeps secrets write-only and turns bug reports into local archives for the operator's mail client, giving model training, dataset compilation and the desktop GUI one reproducible foundation.
